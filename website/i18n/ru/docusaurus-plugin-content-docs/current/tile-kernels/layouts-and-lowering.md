# Раскладки и понижение {#layouts-and-lowering}

`lower::lower(program, &lowering, params, device)` превращает тайловую программу в программу
Svod, список инструкций которой уже упорядочен. `Lowering` содержит всё, что не решал автор:
`Target`, `Schedule`, `WarpGrid` над тайлом блока и признак swizzle для строк разделяемой памяти.
Каждая конфигурация ядра строит свой (`GemmCfg::lowering`, `FaCfg::lowering`,
`NormCfg::lowering`).

| Шаг | Модуль | Действие |
|---|---|---|
| 1. Развёртка расписания | `schedule::expand` | Каждый `Pipeline` становится циклами, ветвлениями и явными инструкциями `Sync` |
| 2. Материализация операндов | `lower` | Операнд `mma` в разделяемой или глобальной памяти получает явную загрузку в свежий регистровый тайл |
| 3. Барьеры | `lower::sync` | Барьеры вставляются вокруг обращений автора к разделяемой памяти |
| 4. Вывод раскладок | `layouts::infer` | Каждый регистровый тайл получает раскладку; конфликты получают `Relayout` |
| 5. Выпуск | `lower/emit.rs` | Инструкции выпускаются в порядке программы в `UOp::linear_program` |

## Линейные раскладки над F2 {#f2-linear-layouts}

`layout::Layout` — линейное отображение над GF(2) из битов входных измерений в биты выходных
(формулировка «Linear Layouts» из Triton). Измерения — `Dim::{Reg, Lane, Warp, Block, Row,
Col}`. Отображение хранит по одному базисному вектору на входной бит. Любой фрагмент вендора,
любой XOR-swizzle и любой план `ldmatrix` — такое отображение. Вот аккумулятор PTX
`mma.m16n8k16` из `layout/atoms.rs`:

```rust
/// PTX `mma.m16n8k16` C/D fragment (16×8, M×N): `row = g + 8·(c/2), col = 2t + c%2`.
pub fn mma_sync_c() -> Layout {
    Layout::from_bases(
        [(Row, 16), (Col, 8)],
        &[(Reg, &[[0, 1], [8, 0]]), (Lane, &[[0, 2], [0, 4], [1, 0], [2, 0], [4, 0]])],
    )
}
```

В алгебре есть `compose`, `inverse`/`pseudo_inverse`, `product` (замостить одну раскладку
другой), `transpose`, `sublayout` и `slice`. Тесты в `test/unit/layout.rs` исчерпывающе
сверяют каждый атом с закрытой формой, которую он кодирует.

Раскладка регистрового тайла — `layouts::TileLayout { frag, reps, warps }`. Она содержит
фрагмент над `(Reg, Lane)`, повторённый `reps` раз внутри подтайла каждого варпа, и координаты
подтайлов варпов.

## Атомы {#atoms}

`atoms::MmaAtom` — одна инструкция матричного ядра с раскладками операндов `a`, `b` и `c`. Её
находит `Target::mma(dtype_in, dtype_out)`. Ядро никогда её не называет: вывод берёт раскладки
операндов из атома, который потребляет значения.

| Цель | Атом (bf16/f16 → f32) | Раскладки фрагментов |
|---|---|---|
| CUDA | `mma.sync` m16n8k16 | `mma_sync_a`, `mma_sync_b`, `mma_sync_c` |
| AMD CDNA | MFMA 16×16×16 | `mfma_16x16x16` |
| AMD RDNA3 / RDNA4 | WMMA 16×16×16 | `wmma_gfx11_*` / `wmma_gfx12` |
| Apple | simdgroup 8×8×8 | `simdgroup_8x8` |

Таблицы ядер есть и на железе сегодня работает только строка CUDA (см. [Переносимость](./portability)).

## Вывод раскладок {#layout-inference}

1. **Атомы задают начальные раскладки.** `mma` даёт своим операндам и результату раскладки
   атома, замощённые по `WarpGrid` (`layouts::mma_layouts`).
2. **Поэлементные операции унифицируются.** Операнды и результат `binary`, `cast`, `where_` и
   переносимые значения цикла делят одну раскладку.
3. **Несвязанные тайлы берут естественную раскладку.** В неподвижной точке тайл, который ничем
   не ограничен, получает `layouts::natural`: каждый лейн держит короткий вектор-строку до 8
   элементов, лейны обходят столбцы, затем строки, а варпы делят строки. Тайлы получают
   раскладку раньше векторов.
4. **Векторы следуют за своим тайлом.** Вектор `[rows, 1]` или `[1, cols]`, например выход
   `reduce` или строка смещения, требуется в той раскладке строки или столбца, которую задаёт его
   тайл. Вывод не назначает ему раскладку по умолчанию отдельно от тайла.
5. **Конфликты превращаются в перекладки.** Для значения, которое два потребителя хотят
   по-разному, вставляется `TileOp::Relayout`. `TileLayout::relayout` классифицирует её как
   `Identity`, `RegPermute` (внутри каждого лейна), `LaneShuffle` или `ViaSmem`. Сейчас
   эмиттер понижает и `LaneShuffle`, и `ViaSmem` через разделяемую память.

## Шаблоны расписания {#schedule-templates}

`schedule::Schedule::Uniform { prefetch, unroll }`: каждый варп и загружает, и вычисляет.

| `prefetch` | Развёртка `pipeline(extent, stages, …)` |
|---|---|
| `CpAsync`, `stages ≥ 2` | Один цикл из `extent + stages − 1` итераций. Каждая итерация ждёт, пока в полёте останется не более `stages − 2` групп копий, затем ставит барьер и потребляет шаг `i − (stages − 1)`. Потом она запускает копии `cp.async` шага `i` в слот, освобождённый итерацией раньше, и фиксирует их одной группой (пустая группа после конца сохраняет счёт одинаковым). |
| `CpAsync`, `stages = 1` | Копия, фиксация, ожидание всех, барьер, потребление, барьер. |
| `RegisterStaged` (2 стадии) | Загрузки global → регистры для шага `i`, потребление шага `i − 1`, запись регистры → shared, барьер. |

`unroll` копирует тело цикла по разу на слот кольца, чтобы арифметика слотов сворачивалась в
константы. Помогает ли это, замеряется для каждой конфигурации, а не предполагается (см.
таблицу GEMM в [Библиотеке ядер](./kernel-library#gemm)).

Асинхронные и поэтапные копии принадлежат шаблону, который сам ставит для них барьеры. Проход
`lower::sync` покрывает остальное: тайл в разделяемой памяти, записанный синхронной копией,
отгораживается барьером до чтения другим потоком, а тайл, прочитанный после последнего
барьера, — до перезаписи.

## Выпуск {#emission}

Эмиттер выписывает инструкции каждой инструкции программы в порядке программы внутри заранее
линеаризованной программы, так что топологическая сортировка линеаризатора Svod никогда не
запускается для ядра tk3. Глобальные обращения за границами view защищены: загрузки читают
ноль, записи отбрасываются. Строки разделяемой памяти XOR-swizzle'ятся 16-байтными кусками,
когда число кусков в строке — степень двойки. Загрузки 16-битных тайлов из shared в регистры
используют `ldmatrix.x4`, где позволяет раскладка. Бэкенд CUDA размещает разделяемую память
сверх статического лимита 48 KB в одном динамическом массиве. Кандидаты конфигурации
фильтруются по opt-in лимиту цели (`Target::smem_bytes`).

:::note[Инварианты держит эмиттер, а не автор]
Чистые значения выписываются на том уровне цикла, которого требуют их входы. Обращения к
регистрам скалярные. Обращения к shared и global — векторные обращения `SHRINK`. Защищённые
записи находятся внутри `If`. Переносимые значения перемещаются в свой `phi` в конце блока,
который их определяет. Эти правила соблюдаются в `lower/emit.rs`, и автор ядра с ними не
сталкивается.
:::

`lower::Error::Unsupported` возвращается для того, что записывается, но пока не понижается:
роли варпов, барьеры ролей, инструкции `raw`, транспонирование регистров и асинхронные копии
на цели не-CUDA. `TK3_DUMP_LIST=1` печатает выпущенный список (см. [Тестирование и отладка](./testing-and-debugging)).
