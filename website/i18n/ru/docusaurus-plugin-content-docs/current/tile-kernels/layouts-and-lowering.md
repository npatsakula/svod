# Раскладки и понижение {#layouts-and-lowering}

`lower::lower(program, &lowering, params, device)` превращает тайловую программу в программу
Svod, список инструкций которой уже упорядочен. `Lowering` содержит то, чего не говорит программа:
`Device` (цель и её стоимости) и матричную инструкцию, на которой выпускаются произведения
(`core`): `Lowering::new(&device)` для ядра уровня варпа, `GemmCfg::lowering` и `FaCfg::lowering`
для ядра своей конфигурации. `WarpGrid` над тайлом блока (`Kernel::warps`) и расписание каждого
кольца (`Ring` у `pipeline`) принадлежат самой программе; строки разделяемой памяти всегда
XOR-swizzle. `lower::standalone(program, &lowering)` понижает для цели без подключённого
устройства, а `lower::render` возвращает текст LLVM, который получил бы компилятор бэкенда.

| Шаг | Модуль | Действие |
|---|---|---|
| 1. Материализация операндов | `lower` | Операнд `mma` в разделяемой или глобальной памяти получает явную загрузку в свежий регистровый тайл; на ядре варпгруппы разделяемые операнды остаются на месте |
| 2. Барьеры | `lower::sync` | Эффекты на разделяемую память ограждаются: барьерами, а перед использованием тайла асинхронной копии — фиксацией и ожиданием. `Pipeline` здесь пока одна инструкция, чей шаблон сам ограждает своё кольцо, поэтому проход ставит ограждения только там, где кольцо встречается с окружающим кодом |
| 3. Развёртка расписания | `schedule::expand` | Каждый `Pipeline` становится циклами, ветвлениями и явными инструкциями `Sync` |
| 4. Вывод раскладок | `layouts::infer` | Каждый регистровый тайл получает раскладку; конфликты получают `Relayout` |
| 5. Ориентация разделяемой памяти | `lower` | Выделение разделяемой памяти, заполняемое через регистры, хранится вдоль той оси, по которой идут фрагменты его читателей, так что сбор данных — это 16-байтные загрузки; тайлы `cp.async` остаются построчными |
| 6. Выпуск | `lower/emit/` | Инструкции выпускаются в порядке программы в `UOp::linear_program` |

`lower` завершается с `Error::Grid`, когда число варпов программы не равно числу варпов сетки
варпов или не кратно ему при наличии инструкции `Warps` в теле, и с `Error::DivergentBarrier`,
когда барьер блока стоит под ветвлением по варпу, которое часть варпов пропустила бы.

## Линейные раскладки над F2 {#f2-linear-layouts}

`layout::Layout` — линейное отображение над GF(2) из битов входных измерений в биты выходных
(формулировка «Linear Layouts» из Triton). Измерения — `Dim::{Reg, Lane, Warp, Block, Row,
Col}`. Отображение хранит по одному базисному вектору на входной бит. Любой фрагмент вендора,
любой XOR-swizzle и любой план `ldmatrix` — такое отображение. Вот аккумулятор PTX
`mma.m16n8k16` из `layout/atoms.rs`:

```rust
/// PTX `mma.m16n8k16` C/D fragment (16×8, M×N): `row = g + 8·(c/2), col = 2t + c%2`.
pub fn mma_sync_c() -> Layout {
    Layout::from_bases(
        [(Row, 16), (Col, 8)],
        &[(Reg, &[[0, 1], [8, 0]]), (Lane, &[[0, 2], [0, 4], [1, 0], [2, 0], [4, 0]])],
    )
}
```

В алгебре есть `identity`, `zeros`, `from_bases`, `transpose`, `product` (замостить одну
раскладку другой), `sublayout` и `apply`. Тесты сверяют каждый атом с формулами лейнов из
документации ISA вендоров (`test/unit/atoms.rs`) и с закрытыми формами tk1
(`test/unit/layout.rs`).

Раскладка регистрового тайла — `layouts::TileLayout { frag, reps, warps }`. Она содержит
фрагмент над `(Reg, Lane)`, повторённый `reps` раз внутри подтайла каждого варпа, и координаты
подтайлов варпов.

## Атомы {#atoms}

`atoms::MmaAtom` — одна инструкция матричного ядра с раскладками операндов `a`, `b` и `c`. Её
находит `Target::mma(dtype_in, dtype_out)`. Ядро никогда её не называет: вывод берёт раскладки
операндов из атома, который потребляет значения.

| Цель | Атом (bf16/f16 → f32) | Раскладки фрагментов |
|---|---|---|
| CUDA | `mma.sync` m16n8k16 | `mma_sync_a`, `mma_sync_b`, `mma_sync_c` |
| CUDA sm_90 | `wgmma` m64nNk16, четыре варпа разом | `wgmma_a`, `wgmma_c`; `B` через дескриптор, в регистрах не держится |
| AMD CDNA | MFMA 16×16×16 | `mfma_16x16x16` |
| AMD RDNA3 / RDNA4 | WMMA 16×16×16 | `wmma_gfx11_input`, `wmma_gfx11_acc` / `wmma_gfx12` |
| Apple | simdgroup 8×8×8 (только атом, ядер нет) | `simdgroup_8x8` |

У каждой цели с ядрами есть также атом 8-битных целых в i32 (`Target::geometry_of(Int8)`):
`mma.sync` m16n8k32 s8 и MFMA 16×16×32 i8 на CDNA держат байты 16-битных фрагментов при вдвое
большей глубине (`mma_sync_a8`, `mma_sync_b8`, `mfma_16x16x32_i8`); WMMA `iu8` на RDNA сохраняет
16-битные раскладки при глубине 16. Его `m` и `n` — те же, что у 16-битного атома. Планировщик
оценивает 16-битную геометрию (`Target::geometry`), кроме задачи над 8-битными строками.

`atoms::GroupMmaAtom` — инструкция варпгруппы: четыре соседних варпа вместе выдают произведение
64 × n над операндами, которые читаются из разделяемой памяти через дескрипторы (`B` всегда,
`A` — если это не регистровый тайл); аккумулятор распределён по группе, и каждый варп держит
16 строк в раскладке C `mma.sync`. Конфигурация с `core` = `Core::Group` понижает свои
произведения на него: строки сетки — варпгруппы, разделяемые операнды остаются на месте, а не
загружаются, и эмиттер записывает каждое произведение одной цепочкой `wgmma` над
swizzled-строками кольца (режим swizzle дескриптора — собственный XOR понижения,
`layouts::Swizzle`). Это ядро на sm_90 предлагают и конфигурации GEMM, и конфигурации внимания.

## Вывод раскладок {#layout-inference}

1. **Атомы задают начальные раскладки.** `mma` даёт своим операндам и результату раскладки
   атома, замощённые по `WarpGrid` (`MmaAtom::issue`), и выпускается в той ориентации
   (`ir::Orient`), которая оставляет программе наименьшую стоимость перекладок при `Costs`
   понижения: `Cᵀ = Bᵀ·Aᵀ` — та же инструкция с переставленными слотами, так что на квадратном
   атоме аккумулятор можно бесплатно держать как операнд следующего произведения. Произведение,
   результат которого раздаётся (`TileOp::Deal`, очереди лейнов списка), выпускается в той
   ориентации, которая распределяет строку по наименьшему числу лейнов (`MmaAtom::narrow`): там
   раздача — переименование регистров, как её и оценивает слой операций. Автор может
   закрепить ориентацию (`Kernel::mma_oriented`).
2. **Поэлементные операции унифицируются.** Операнды и результат `binary`, `cast`, `where_`,
   `mul_add` и переносимые значения цикла делят одну раскладку.
3. **Несвязанные тайлы берут естественную раскладку.** В неподвижной точке тайл, который ничем
   не ограничен, получает `layouts::natural`: каждый лейн держит короткий вектор-строку до 8
   элементов, лейны обходят столбцы, затем строки, а варпы делят строки.
4. **Векторы следуют за своим тайлом.** Вектор `[rows, 1]` или `[1, cols]`, например выход
   `reduce` или строка смещения, требуется в той раскладке строки или столбца, которую задаёт
   его тайл.
5. **Конфликты превращаются в перекладки.** Для значения, которое два потребителя хотят
   по-разному, вставляется `TileOp::Relayout`. `TileLayout::relayout` классифицирует её как
   `Identity`, `RegPermute` (внутри каждого лейна, бесплатно), `Exchange` (каждый регистр
   берётся перемещениями по lane-xor от фиксированных партнёров) или `ViaSmem`. `Exchange`
   сохраняется, только пока его работа дешевле круга через разделяемую память
   (`Relayout::work × Costs::lane_move < Costs::smem_trip`). Эмиттер понижает `Exchange`
   перемещениями между лейнами, которые даёт цель (`atoms::LaneMove`: `shfl.sync` на CUDA, DPP
   и `permlanex16` на RDNA, `ds_bpermute` на CDNA).

## Шаблоны расписания {#schedule-templates}

`schedule::expand` разворачивает каждый `Pipeline` по его `Ring { stages, unroll, crews }` и
`Fill` цели. Одна бригада: каждый варп и загружает, и вычисляет. Две бригады: варпы блока в двух
бригадах со сдвигом на кластер над одним слотом, заполняемым через регистры (GEMM на CDNA,
`GemmCfg::crews == 2`).

| Заполнение | Развёртка `pipeline(extent, ring, …)` |
|---|---|
| `Fill::CpAsync`, `stages ≥ 2` | Один цикл из `extent + stages − 1` итераций. Каждая итерация ждёт, пока в полёте останется не более `stages − 2` групп копий, затем ставит барьер и потребляет шаг `i − (stages − 1)`. Потом она запускает копии `cp.async` шага `i` в слот, освобождённый итерацией раньше, и фиксирует их одной группой (пустая группа после конца сохраняет счёт одинаковым). |
| `Fill::CpAsync`, `stages ≥ 3`, ядро варпгруппы, потребление, чьи произведения питают только произведения | То же, но цепочки `wgmma` потребления остаются в полёте во время следующего заполнения: заново заполняется слот, потреблённый два прохода назад, а после каждого потребления каждый поток ждёт завершения всех своих цепочек, кроме самой молодой (`Sync::WaitProducts`). |
| `Fill::CpAsync`, `stages = 1` | Копия, ожидание, потребление и барьер перед повторным заполнением слота. |
| `Fill::Staged`, 2 стадии | Три цикла над одной индукционной переменной: первый проход загружает шаг 0 в регистры и записывает его в свой слот; установившийся проход загружает шаг `i` в регистры, ставит ограждение, потребляет шаг `i − 1`, ставит ограждение и записывает регистры в слот шага `i`, без единого ветвления в теле (на RDNA ограждения держат загрузки перед произведениями, а запись — после них); последний проход только потребляет. |
| `Fill::Staged`, 1 стадия | Те же три цикла над одним слотом: запись ждёт за барьером, пока каждый варп закончит со слотом, а затем снова ставит барьер, так что в ту же разделяемую память помещается вдвое более глубокий тайл. |
| две бригады | Проход режется по произведениям на кластеры загрузки и кластеры произведений, после каждого — барьер блока, так что произведения одной бригады идут из регистров с повышенным приоритетом выдачи, пока другая бригада загружает. |

`unroll` копирует тело цикла по разу на слот кольца, чтобы арифметика слотов сворачивалась в
константы; тюнер замеряет оба варианта. Асинхронные и поэтапные копии принадлежат шаблону,
который сам их ограждает. Проход `lower::sync` покрывает остальное: тайл в разделяемой памяти,
записанный синхронной копией, ограждается до того, как его прочтёт другой поток, а тайл,
прочитанный после последнего ограждения, — до перезаписи.

## Выпуск {#emission}

Эмиттер выписывает инструкции каждой инструкции программы в порядке программы внутри заранее
линеаризованной программы, так что топологическая сортировка линеаризатора Svod никогда не
запускается для ядра tk. Глобальные обращения за границами view защищены: загрузки читают
ноль, записи отбрасываются. Строки разделяемой памяти XOR-swizzle'ятся 16-байтными кусками,
когда число кусков в строке — степень двойки (`layouts::Swizzle`). Загрузки 16-битных тайлов из shared в регистры
используют `ldmatrix.x4`, где позволяет раскладка, а 8-битных — его нетранспонированную форму над 16×32 байтами; на RDNA4 загрузки из global в регистры
используют `global_load_tr_b128`, где раскладка совпадает с той, что она оставляет. Инструкция
`Warps` выполняет своё тело на каждом варпе отдельно, с собственными копиями и барьерами.
На AMD `exp2` для f32 — это аппаратный `v_exp_f32`, который обнуляет результаты ниже 2⁻¹²⁶.
На CUDA разделяемая память сверх 48 KB — один динамический массив; кандидаты фильтруются по
`Target::smem_bytes`.

:::note[Инварианты держит эмиттер, а не автор]
Чистые значения выписываются на том уровне цикла, которого требуют их входы. Обращения к
регистрам скалярные. Обращения к shared и global — векторные обращения `SHRINK`. Защищённые
записи находятся внутри `If`. Переносимые значения перемещаются в свой `phi` в конце блока,
который их определяет. Цикл, чей extent может стать отрицательным, не делает ни одной
итерации (конец диапазона ограничен нулём снизу).
:::

`TK_DUMP_LIST=1` печатает выпущенный список (см. [Тестирование и отладка](./testing-and-debugging)).
