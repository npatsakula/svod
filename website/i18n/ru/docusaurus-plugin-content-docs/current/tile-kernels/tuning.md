# Автотюнинг при первом использовании

Таблица тайлов ядра — это пространство поиска, а не ответ. У GEMM от трёх до пяти тайлов на
семейство, у flash attention четыре тайла варпа, у single-query attention несколько разбиений K/V,
и победитель зависит от формы, числа вычислительных блоков устройства и его частоты. Поэтому, когда
устройство впервые встречает форму, `svod-tk` компилирует и замеряет каждого подходящего кандидата,
оставляет самого быстрого и запоминает его на диске. Весь механизм — это `tk/src/tune.rs`.

---

## Что происходит при первом запуске

`GemmPolicy::tuned`, `FaPolicy::tuned` и `SqPolicy::tuned` (в `tk/src/kernels/`) выполняют одну и ту
же последовательность через `TuneStore::select`:

1. **Фильтр.** Таблица сужается до кандидатов, которые тайлят форму (а для GEMM ещё и поддерживают
   запрошенный `Epilogue`). Один кандидат или ни одного — возвращается статический выбор, ничего не
   замеряется.
2. **Мемо.** Общий для процесса `HashMap<TuneKey, usize>` отвечает на повторную форму без сборки ядра:
   план спрашивает одну и ту же форму по разу на узел.
3. **Хранилище.** При промахе мемо `SINK` каждого кандидата собирается на буферах-заглушках и получает
   отпечаток (`kernel_fingerprint`). Дайджесты входят в строку хранилища, так что изменение тела ядра
   приводит к повторному замеру. Строка ищется в файле устройства.
4. **Замер.** При промахе хранилища каждый кандидат проходит `compile_kernel` на синтетических
   операндах нужной формы (`Tensor::randn`, приведение к dtype, перенос на устройство). Первый
   собравшийся поднимает частоту: `warm_clock` диспатчит его, пока время не перестанет падать или не
   пройдёт 1.5 с; уже нагруженное устройство выходит на плато за несколько прогонов. Затем
   `round_robin_min` по очереди замеряет всех кандидатов три раунда и оставляет минимум каждого, так
   что никого не судят на частоте, на которой не мерили остальных.
5. **Сохранение** самого быстрого: в мемо и в файле хранилища. Кандидат, который не собирается или не
   диспатчится, пропускается; если не удаётся ни один, ничего не кэшируется и используется
   статический выбор.

В файл попадает только замеренный победитель. `select_with` — та же политика, но замер передаёт
вызывающий код; так юнит-тесты в `tk/src/test/unit/tune.rs` проверяют её без GPU.

## Ключ и хранилище

```rust
// tk/src/tune.rs
pub struct TuneKey {
    pub kernel: &'static str,   // "gemm_nt", "flash_attention", "sq_attention"
    pub device: String,         // "<arch target name>-<compute units>cu"
    pub shape: Vec<usize>,      // the kernel's own shape tuple, dtype width and flags included
    pub config: u64,            // a digest of the candidate set (and anything else the graphs vary with)
}
```

Ключ GEMM — `[m, k, n, dtype.bytes(), epilogue.code()]`; flash attention —
`[b, n, h, h_kv, d, causal, mask.code(), dtype.bytes()]`. Изменение таблицы меняет `config`, так что
новый кандидат приводит к повторному замеру.

Хранилище — один файл на устройство и версию крейта, одна строка на запись:

```text
<kernel>|<device>|<shape>|<builds digest> <winning index> <ns>
```

в первом из мест:

| Расположение | Когда |
|---|---|
| `$SVOD_TK_TUNE_DIR/` | переменная задана |
| `$XDG_CACHE_HOME/svod/tk_tune/` | иначе, если задана `XDG_CACHE_HOME` |
| `$HOME/.cache/svod/tk_tune/` | в остальных случаях |

Имя файла — строка устройства, в которой не-алфавитно-цифровые символы заменены
(`gfx1201_64cu-v0.1.0.txt`). Запись перечитывает файл, сливает и атомарно переименовывает,
так что два процесса, тюнящих одновременно, теряют самое большее по последней строке друг друга.
Нечитаемый или незаписываемый каталог — это промах, а не ошибка; без записываемого корня хранилище
живёт только в памяти.

## Как выключить

| Механизм | Эффект |
|---|---|
| `SVOD_TK_TUNE=0` | никаких замеров; каждая политика возвращает свой статический выбор (`GemmPolicy::cfg`, `FaPolicy::config`, разбиение политики) |
| `svod_tk::tune::set_enabled(false)` | то же самое из кода, с приоритетом над окружением на весь процесс; тестовые обвязки вызывают его, чтобы тест ядра не тюнил каждую затронутую форму |
| `gemm_nt_with(x, w, cfg)`, `flash_attention_tuned(q, k, v, opts, policy)`, `SqAttentionOpts::split` | обойти политику для одного запуска собственной функцией выбора |

Тюнинг пропускается и тогда, когда устройство не ставит таймстампы диспатча (`dispatch_gpu_ns`
возвращает `None`): сравнивать было бы нечего.

## Что тюнится

| Ядро | Кандидаты | Таблица |
|---|---|---|
| `gemm_nt` | каждый `GemmCfg` из таблицы семейства, который тайлит `(m, k, n)` и поддерживает эпилог | `CUDA_TILES` (2), `RDNA_TILES` (3), `RDNA4_TILES` (5) в `tk/src/kernels/gemm.rs` |
| `flash_attention` | каждая пара `(q_blk, kv_blk)` из `FA_TILES`, чьи двойные буферы K/V помещаются в разделяемую память и чей блок делит `N` | `[(16,16), (16,32), (16,64), (32,32)]` в `tk/src/kernels/fa.rs` |
| `single_query_attention` | делители `N`, ближайшие к бюджету резидентных волн устройства, при которых на кусок приходится не меньше 15 итераций | `SqPolicy::candidates` в `tk/src/kernels/sq_attention.rs` |

Статический выбор, к которому откатывается каждая политика, сам замерен — на одном чипе каждого
семейства: `GemmPolicy::cfg` для GEMM предпочитает самый широкий тайл, если только его сетка не
перестаёт заполнять вычислительные блоки устройства `resident` раз; `FaPolicy::tile` берёт более
высокий тайл варпа, только когда сетка запуска покрывает устройство, а размер головы ниже границы
семейства. Тюнинг существует потому, что эти точки перехода сдвигаются вместе с формой.

:::tip[Как прочитать замер]
`SVOD_DEVICE=AMD:0 cargo test -p svod-tk --lib tune::gemm_first_use -- --ignored` прогоняет
настоящую последовательность на временном хранилище и проверяет, что появились один файл и одна строка,
а второй запрос читает её обратно без замера. Чтобы узнать, что выбрано для формы в вашем прогоне,
прочитайте файл: индекс — это позиция в таблице, названной выше.
:::

Цена платится один раз на форму и устройство: несколько компиляций плюс примерно две секунды замеров
на холодном GPU. Модель с группированными формами (Qwen3 округляет длины последовательностей до
кратных `FLASH_ATTENTION_SEQUENCE_MULTIPLE`) тюнит несколько строк, а дальше все батчи идут из мемо.
