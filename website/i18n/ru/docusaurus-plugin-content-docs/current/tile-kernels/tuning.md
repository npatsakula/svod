# Тюнинг {#tuning}

У каждой операции есть список кандидатов на форму в `ops::config` (таблицы см. в
[Библиотеке ядер](./kernel-library)). Первый кандидат — то, что работает без тюнинга.
Хранилище тюнинга замеряет весь список, когда устройство впервые встречает форму, и сохраняет
победителя.

Лучшего фиксированного выбора по умолчанию оказалось недостаточно. GEMM в Nemotron (M = 704,
N 512–2048) работали примерно на 14 TFLOP/s со старой фиксированной лестницей тайлов: 48 блоков
на 28 SM. С хранилищем тюнинга их среднее время упало с 76.5 примерно до 60 µs на RTX 3060.

## Когда происходит замер {#when-measurement-happens}

Операция замеряет там, где её вызывают, во время построения графа, и никогда — внутри
выполняющегося плана. Каждый кандидат собирается как программа, запускается на временных
буферах полной ёмкости, где каждая переменная времени выполнения связана со своим максимумом, и
замеряется:

| Шаг | Настройка |
|---|---|
| Прогрев | 500 ms непрерывных запусков (RTX 3060 в простое работает на 210 MHz) |
| Раунды | 4 раунда round-robin по всем кандидатам |
| В каждом раунде | 10 ms поддерживающих запусков, затем 5 профилируемых, сохраняется минимум каждого кандидата |
| Время запуска | GPU-метки времени самого долгого ядра |

Кандидат — это список программ: ядро плюс слияние его частичных результатов для разбитого
внимания, а его время — сумма времён его программ. Кандидат, который не удалось собрать или
запустить, пропускается. Если ничего не замерилось, используется первый кандидат и ничего не
сохраняется.

## Хранилище {#the-store}

| Что | Значение |
|---|---|
| Каталог | `$SVOD_TK3_TUNE_DIR`, иначе `$XDG_CACHE_HOME/svod/tk3_tune`, иначе `~/.cache/svod/tk3_tune` |
| Файл | По одному на устройство и версию крейта, например `sm_86_28sm-v0.2.0.txt` |
| Строка | `op\|device\|dtype\|shape\|candidates\|programs index ns` |
| Ключ | `tune::TuneKey { op, device, dtype, shape, candidates }`, где `device` — архитектура и число SM (`sm_86-28sm`) |

Строка из реального хранилища: attention, bf16, форма `[batch, t, tk, heads, kv_heads, d]`,
кандидат 2 победил с 61.4 µs.

```text
attention|sm_86-28sm|BFloat16|1x704x704x8x8x64|3733e8921b15aa79|77aee9d5c98fa463 2 61440
```

Поле `programs` — отпечаток собранных программ-кандидатов и их понижений, поэтому изменение ядра
приводит к повторному замеру. Запись перечитывает, сливает и атомарно заменяет файл.
Нечитаемое или незаписываемое хранилище считается промахом, а не ошибкой. Мемо процесса
отвечает на повторные вызовы, ничего не собирая.

## Как отключить {#switching-it-off}

| Как | Эффект |
|---|---|
| `SVOD_TK3_TUNE=0` | Замеры выключены; работает первый кандидат |
| `svod_tk3::tune::set_enabled(false)` | То же для текущего процесса, поверх окружения (так делают тесты) |

`tune::TuneStore::at(root)` создаёт хранилище в другом корне или только в памяти при `None`.
`tune::measure(candidates)` так же замеряет любой список `tune::Candidate`
(`Vec<(Program, Lowering)>`).

## Замеры-пробы {#probes}

Пробы — это тесты с `#[ignore]`, которые печатают время и ничего не проверяют. Запускайте их по
одной на простаивающем GPU:

```bash
SVOD_DEVICE=CUDA:0 cargo test -p svod-tk3 --lib --release -- --ignored --nocapture --test-threads=1 gemm_candidates_probe
```

| Проба | Печатает |
|---|---|
| `gemm_throughput_probe` | Конфигурации GEMM tk3 против tk1 на 4096³, TFLOP/s |
| `gemm_candidates_probe` | Каждого кандидата GEMM на формах проекций Nemotron и 4096³, выбор без тюнинга и победителя |
| `attention_throughput_probe` | Flash attention (B 4, H 8, T 2048; d 64/128, causal и без) против tk1 |
| `decode_throughput_probe` | Self и cross attention одного шага декодера Whisper large-v3 против tk1 |
| `first_execution_probe` | Стоимость на хосте сборки, понижения и подготовки GEMM tk3 против GEMM графа |

Последняя проба замерила стоимость на хосте, которая сформировала `launch.rs`. Понижение тела
GEMM стоит 2.3 ms, поэтому пониженные тела мемоизируются по программе, понижению, устройству и
формам плейсхолдеров (попадание стоит 30 µs). Планирование тела всё ещё обходится примерно на
0.35 ms дороже, чем GEMM графа, на этапе подготовки.
