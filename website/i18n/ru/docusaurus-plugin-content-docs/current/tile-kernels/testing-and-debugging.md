# Тестирование и отладка {#testing-and-debugging}

Каждое ядро tk3 проверяется на двух уровнях. На хосте его тайловая программа выполняется в
интерпретаторе и сверяется с прямым эталоном. На устройстве CUDA пониженное ядро сверяется с
интерпретатором или с графовым запасным вариантом самой операции. Тесты сравнивают значения с
допусками, а не хэши IR.

## Интерпретатор {#the-interpreter}

`interp::run(&program, params, vars)` исполняет тайловую программу на хосте. Он принимает по
одному `Vec<f64>` на параметр и возвращает все параметры после выполнения. Каждый блок
выполняет свои инструкции по порядку, а конвейер выполняется как последовательное чередование.
Каждое значение округляется до своего типа элемента (`interp::round_to`), так что результат —
то, что корректное понижение должно воспроизвести с точностью до порядка накопления.
Переменные времени выполнения связываются по имени:

```rust
let out = run(&prog, vec![a.clone(), b.clone(), vec![0.0; m * n]], &[("b", 1)]).unwrap();
```

Он возвращает `interp::Error::{UnboundVar, ParamSize, Raw}`. Потоки и барьеры он не
моделирует, поэтому ошибки упорядочивания проявляются только на устройстве.

## Файлы тестов {#test-files}

| Файл | Уровень | Что проверяет |
|---|---|---|
| `layout.rs`, `layouts.rs`, `atoms.rs` | хост | Законы алгебры F2, каждый атом против его закрытой формы, результаты вывода |
| `interp.rs`, `schedule.rs`, `build.rs` | хост | Семантику интерпретатора, развёртку конвейера |
| `ops_plan.rs` | хост | `Plan` и ошибки каждой операции по форме, типу данных и цели |
| `attention.rs`, `heads.rs`, `rows.rs` | хост + устройство | Программу против эталона f64, затем пониженное ядро против программы |
| `device.rs`, `parts.rs` | устройство | GEMM (каждую конфигурацию, которую может выбрать слой операций) и составные части внимания против интерпретатора |
| `ops.rs` | устройство | Каждую операцию против её графового варианта на неудобных формах, с выключенным тюнингом |
| `tune.rs` | хост + устройство | Сохранение и чтение хранилища, стабильность ключей, реальный тюнинг GEMM |

Тесты на устройстве пропускаются со строкой `skipped: no CUDA device`, если `SVOD_DEVICE` не
указывает на устройство CUDA. Весь набор на GPU запускается последовательно:

```bash
SVOD_DEVICE=CUDA:0 cargo test -p svod-tk3 --lib --release -- --test-threads=1
```

Проверка на уровне модели для Nemotron (настоящие веса, сгенерированные эталоны):

```bash
SVOD_DEVICE=CUDA:0 cargo test -p svod-model --release --lib nemotron_diar::parity::half_precision -- --ignored --nocapture --test-threads=1
```

## Запустилось ли ядро? {#did-the-kernel-run}

Операция, ушедшая на запасной вариант, строит операции графа вместо `CALL`. Тесты в `ops.rs`
ищут имя ядра среди вызовов результата:

```rust
fn assert_kernel(t: &Tensor, name: &str) {
    let calls: Vec<String> = t
        .uop()
        .toposort()
        .iter()
        .filter_map(|u| match u.op() {
            Op::Call(ops::Call { info, .. }) => info.name.clone(),
            _ => None,
        })
        .collect();
    assert!(calls.iter().any(|n| n == name), "no {name} kernel among {calls:?}");
}
```

Чтобы предсказать путь без устройства, вызовите планировщик `ops::shape` (см. [Слой операций](./op-layer#kernel-or-graph)).

## Переменные окружения {#environment-variables}

| Переменная | Эффект |
|---|---|
| `TK3_DUMP_LIST=1` | Печатает каждую выпущенную инструкцию (`[i] id op dtype <- sources`) при понижении программы. Тела мемоизируются, поэтому печатается только первое понижение каждой программы |
| `SVOD_SPEC_DEBUG=1` | Когда программа не проходит проверку спецификации IR, печатает отвергнутую инструкцию и её дерево |
| `SVOD_TK3_TUNE=0` | Без замеров; работает первый кандидат (см. [Тюнинг](./tuning)) |
| `SVOD_DEVICE=CUDA:0` | Запуск на GPU (устройство по умолчанию решает, применимы ли ядра) |

## Профилирование модели {#profiling-a-model}

Пример Nemotron один раз прогревается (заодно заполняя хранилище тюнинга), замеряет запуск, а
затем печатает поядерный отчёт третьего запуска:

```bash
cargo run -p svod-model --release --example nemotron_diarize -- audio_1.wav --dtype bf16 --profile
```

Ядра tk3 появляются под своими именами (`gemm`, `flash_attention`, `heads`, `layer_norm`, …)
рядом с ядрами графа и замеряются так же.

:::tip[Замеряйте на тихом GPU]
RTX 3060 в простое работает на 210 MHz, а любой другой процесс на GPU искажает все числа. Пробы
и хранилище тюнинга сначала прогревают частоту. Запускайте пробы с `--test-threads=1`.
:::
