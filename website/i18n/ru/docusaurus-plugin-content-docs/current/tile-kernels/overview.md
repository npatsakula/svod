# Tile-ядра (tk3) {#tile-kernels-tk3}

Оптимизатор Svod находит быстрые расписания для большей части модели перебором преобразований
циклов. Но некоторые ядра так не найти. Flash attention — это рекуррентность: каждый блок
ключей обновляет текущие максимум и сумму и перемасштабирует аккумулятор, так что единой
редукции, которую можно разбить на тайлы, нет. Быстрый GEMM на GPU с тензорными ядрами держится
на многоступенчатом кольце `cp.async`, загрузках фрагментов через `ldmatrix` и swizzled-раскладке
разделяемой памяти — всё это не шаги перебора циклов. Такие ядра пишутся вручную, и `svod-tk3`
(«tk3») — крейт для их написания.

tk3 заменяет старый крейт `svod-tk` (tk1), который выводится из употребления по мере перехода
моделей на слой операций, описанный здесь.

## Что такое tk3 {#what-tk3-is}

| Часть | Модуль | Что делает |
|---|---|---|
| Тайловая программа | `ir`, `build` | Структурированное дерево инструкций (`Let`, `Copy`, `Loop`, `Pipeline`, `If`) над тайловыми значениями. Строится записывающим билдером `Kernel` в порядке программы и не является DAG. |
| Раскладки | `layout`, `layouts` | Линейные раскладки над F2 (битовые матрицы) для каждого фрагмента и swizzle, назначаемые выводом. Код ядра никогда не называет лейн. |
| Атомы | `atoms` | Инструкции матричных ядер каждой цели, несущие раскладки своих операндов (`mma.sync` на CUDA). |
| Шаблоны расписания | `schedule` | Разворачивают инструкцию `Pipeline` в циклы, группы `cp.async` и барьеры. Автор пишет только тела produce и consume. |
| Понижение | `lower` | Разворачивает расписание, вставляет барьеры по эффектам, выводит раскладки и выпускает заранее линеаризованный список инструкций (`Op::Linear`), так что порядок не решает никакая топологическая сортировка. |
| Ядра | `kernels` | GEMM с эпилогами, flash attention, пролог внимания, LayerNorm/RMSNorm. На входе каждого — структура-спецификация, на выходе — `Program`. |
| Запуск | `launch` | Запускает программу как пользовательское ядро в ленивом графе, мемоизируя пониженные тела. |
| Слой операций | `ops` | `linear`, `attention`, `heads`, `layer_norm`, `rms_norm`, … Всегда возвращают `Tensor`: ядро, когда оно подходит, иначе граф. |
| Интерпретатор | `interp` | Исполняет любую тайловую программу на хосте и даёт эталонные числа без GPU. |
| Хранилище тюнинга | `tune` | Замеряет кандидатов конфигурации каждой операции один раз на форму и устройство и сохраняет победителя на диске. |

```text
model code ──► svod_tk3::ops          always a Tensor; picks a kernel and config or builds the graph op
                   │
                   ▼
              kernels::*               spec ─► tile Program (builder, program order)
                   │
                   ▼
              lower::lower             schedule template ─► operand loads ─► barriers
                   │                   ─► layout inference ─► emission
                   ▼
              Op::Linear program  ──►  custom kernel in the lazy graph ─► LLVM ─► device
```

## Состояние, замерено на RTX 3060 (sm_86) {#status-measured-on-an-rtx-3060-sm_86}

| Что | Результат |
|---|---|
| bf16 GEMM 4096³ | 25.4 TFLOP/s, наравне с tk1. Потолок `mma.sync` bf16→f32 этой карты — 27.9 |
| Flash attention, прямой проход | Не хуже tk1 на каждом замере пропускной способности (размерности головы 64 и 128, causal и без) |
| LayerNorm / RMSNorm | 92% пропускной способности памяти |
| Nemotron-3-Diarization (bf16) | 68.2 → 49–53 ms на четыре шага, 2292 → 1304 запусков, паритет сохранён |

Nemotron использует слой операций для всех своих проекций, нормализаций и внимания. Энкодер
Whisper, ModernBERT, GigaAM, XLM-R/BGE-M3 и Qwen3 вызывают его для проекций и нормализаций.

:::note[Ещё не сделано]
Внимание при декодировании в моделях, ядра свёртки и любые цели, кроме NVIDIA sm_80+ (пути
Hopper, Blackwell и AMD CDNA/RDNA), не реализованы. См.
[Переносимость](./portability).
:::
