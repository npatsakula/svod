# Tile-ядра (tk) {#tile-kernels-tk}

Оптимизатор Svod находит быстрые расписания для большей части модели перебором преобразований
циклов. Но некоторые ядра так не найти. Flash attention — это рекуррентность: каждый блок
ключей обновляет текущие максимум и сумму и перемасштабирует аккумулятор, так что единой
редукции, которую можно разбить на тайлы, нет. Быстрый GEMM на GPU с тензорными ядрами держится
на многоступенчатом кольце `cp.async`, загрузках фрагментов через `ldmatrix` и swizzled-раскладке
разделяемой памяти — всё это не шаги перебора циклов. Такие ядра пишутся вручную, и `svod-tk`
(«tk») — крейт для их написания.

`svod-tk` реализует третью версию тайлового языка («tk3») и остаётся единственным крейтом tile-ядер.
Он заменил tk1, прежний крейт с тем же именем, который удалён вместе со своими
ядрами k-means, kNN и ядрами для Apple; ни одно из них не перенесено. На слое операций работают восемь моделей:
Nemotron-3-Diarization, Whisper (энкодер и внимание шага декодера в режиме кэша), ModernBERT,
BGE-M3/XLM-RoBERTa, Qwen3-Embedding, GigaAM, WavLM и YOLO26 (channels-last, свёртки 3×3 на
`ops::conv2d`).

## Что такое tk {#what-tk-is}

| Часть | Модуль | Что делает |
|---|---|---|
| Тайловая программа | `ir`, `build` | Структурированное дерево инструкций (`Let`, `Copy`, `Loop`, `Pipeline`, `If`, `Warps`) над тайловыми значениями, которое билдер `Kernel` записывает в порядке программы. Это не DAG. |
| Раскладки | `layout`, `layouts` | Линейные раскладки над F2 (битовые матрицы) для каждого фрагмента и swizzle, назначаемые выводом. Код ядра никогда не называет лейн. |
| Атомы | `atoms` | Инструкции матричных ядер каждой цели вместе с раскладками операндов: `mma.sync` (CUDA), `wgmma` (sm_90), WMMA (RDNA3/3.5/4), MFMA 16×16×16 (CDNA). |
| Шаблоны расписания | `schedule` | Разворачивают `Pipeline` в группы `cp.async`, регистровое кольцо из одного или двух слотов или две бригады в режиме ping-pong (GEMM на CDNA). Автор пишет только тела produce и consume. |
| Понижение | `lower` | Вставляет барьеры по эффектам, разворачивает расписание, выводит раскладки и выпускает заранее линеаризованный список инструкций (`Op::Linear`), так что порядок не решает никакая топологическая сортировка. |
| Ядра | `kernels` | GEMM с эпилогами, неявная GEMM-свёртка 3×3 со split-K, flash attention, пролог внимания, LayerNorm/RMSNorm. На входе каждого — структура-спецификация, на выходе — `Program`. |
| Запуск | `launch` | Запускает программу как пользовательское ядро в ленивом графе, мемоизируя пониженные тела. |
| Слой операций | `ops` | `linear`, `conv2d`, `attention`, `heads`, `layer_norm`, `rms_norm`, … Всегда возвращают `Tensor`: используют ядро, когда оно подходит, и граф в остальных случаях. |
| Планировщик | `ops::config` | Ранжирует конфигурации для каждой формы по измеренным стоимостям устройства. |
| Интерпретатор | `interp` | Исполняет любую тайловую программу на хосте и даёт эталонные числа без GPU. |
| Хранилище тюнинга | `tune` | Замеряет кандидатов каждой операции один раз на форму и устройство и сохраняет победителя на диске. |

```text
model code ──► svod_tk::ops          always a Tensor; picks a kernel and config or builds the graph op
                   │
                   ▼
              kernels::*               spec ─► tile Program (builder, program order)
                   │
                   ▼
              lower::lower             operand loads ─► barriers ─► schedule template
                   │                   ─► layout inference ─► emission
                   ▼
              Op::Linear program  ──►  custom kernel in the lazy graph ─► LLVM ─► device
```

## Цели {#targets}

| Цель | Матричное ядро | Заполнение | Где замерено | GEMM 4096³ bf16, TFLOP/s | Внимание d64, TFLOP/s |
|---|---|---|---|---|---|
| CUDA sm_80+ | `mma.sync` m16n8k16, `ldmatrix` | `cp.async` | RTX 3060 (sm_86); RTX 5070, RTX 5090 (sm_120) | 25.9; 65.7 (cuBLAS NN 67.4); 204.8 (cuBLAS NN 218.2) | 24.8; 62.9; 188.5 |
| CUDA sm_90 | плюс `wgmma` (GEMM и внимание) | `cp.async` | H100 PCIe | 423.7 (cuBLASLt 410–524) | 254.9 (FA3 270.1) |
| AMD RDNA4 | WMMA 16×16×16 | регистры, 1–2 слота | RX 9070 XT (gfx1201) | 148.8 (rocBLAS 80) | 117.3 |
| AMD RDNA3 / 3.5 | WMMA 16×16×16 | регистры, 1–2 слота | Strix Halo (gfx1151); gfx1100 скомпилирован, не запускался | 29.7 (rocBLAS NT 32.5) | 26.2 |
| AMD CDNA3 / 4 | MFMA 16×16×16, wave64 | регистры, две бригады в режиме ping-pong | MI300X (gfx942); gfx950 не запускался | 560.0 (hipBLASLt 615) | 281.4 |
| Apple | атом simdgroup 8×8×8 | — | ядер нет | — | — |

Каждое число — выбор тюнера на этой карте, замеренный 2026-10-17 с помощью
`gemm_throughput_probe` и `attention_throughput_probe` (B 4, H 8, T 2048) на коммите 55fb615b,
кроме H100 (251276d9) и MI300X (fc5cc954). Эталоны вендоров в скобках замерены на той же машине.
Цель считается замеренной, только когда на ней проходит
`targets::families_match_the_interpreter_on_the_device`.

На RTX 3060 RMSNorm над 8192×1024 bf16 прокачивает 325 GB/s из 360 доступных карте, а
Nemotron-3-Diarization (bf16, четыре шага) занимает 45.82 ms времени GPU за 1064 запуска против
2292 запусков до tk3.

:::note[Не в этом релизе]
Производители на Hopper TMA и mbarrier (sm_90 выполняет `wgmma`, питаемый через `cp.async`),
Blackwell `tcgen05`, MFMA 32×32, ядра Apple, fp8/int8, обратный проход внимания и вариант свёртки
с подготовкой изображения в разделяемой памяти. См. [Переносимость](./portability#not-in-this-release).
:::
