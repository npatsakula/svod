# Переносимость {#portability}

## Цели {#targets}

`atoms::Target` — всё, что понижение знает о GPU:

| Поле | Значение |
|---|---|
| `arch` | `GpuArch::{Cuda, Amd, Metal}` |
| `wave` | Лейнов в варпе или волне |
| `mma` | Атомы матричных ядер с раскладками операндов |
| `cp_async` | Асинхронные копии global → shared (CUDA sm_80+) |
| `ldmatrix` | Коллективные по варпу загрузки фрагментов 8×8 b16 (CUDA sm_75+) |
| `smem_bytes` | Разделяемая память на блок (opt-in лимит, если устройство его сообщает) |
| `sms` | Число SM или CU, если устройство его сообщает |

`Target::for_device(&spec)` определяет цель по живому устройству. `Target::for_arch(arch)`
строит её по одной архитектуре — так делают тесты на хосте. `atoms::sm86()` — цель RTX 3060 с
28 SM.

| Цель | Атомы и раскладки | Таблицы конфигураций | Понижено и запущено |
|---|---|---|---|
| CUDA sm_80+ (замерено на sm_86) | `mma.sync` m16n8k16, `ldmatrix`, `cp.async` | да | да |
| AMD CDNA (gfx942) | MFMA 16×16×16 | нет | нет |
| AMD RDNA3 / RDNA4 | WMMA 16×16×16 | нет | нет |
| Apple | simdgroup 8×8×8 | нет | нет |

`ops::supported(device)` истинно только там, где есть таблицы конфигураций, поэтому на любом
другом устройстве каждая операция строит свой графовый вариант (`Fallback::Target`). Атомы AMD
и Apple существуют, и тесты на хосте проверяют, что их раскладки покрывают форму инструкции, но
ни одно ядро не было понижено или запущено на этих целях.

## Стратегия {#strategy}

Принятый подход — **одна общая тайловая программа на операцию**. Ядро вроде `kernels/gemm.rs`
пишется один раз над тайловыми значениями и никогда не ветвится по вендору. Для каждой цели
меняются данные, которые выбирают понижение и слой операций:

| Для каждой цели | Где |
|---|---|
| Атомы матричных ядер и их раскладки | `atoms`, `layout/atoms.rs` |
| Механизмы копирования (`cp.async`, `ldmatrix`, поэтапная загрузка через регистры) | Флаги `Target`, эмиттер |
| Шаблоны расписания | `schedule::Schedule` |
| Таблицы кандидатов конфигураций | `ops::config` |

Отдельная программа ядра для одного вендора допускается только как ограниченное исключение.

## Не сделано {#not-done}

| Пункт | Состояние |
|---|---|
| Hopper (sm_90a): wgmma, TMA, mbarrier, шаблон с warp specialization | Не начато; будет замеряться на удалённом H100 |
| Blackwell (sm_100a): tcgen05, тензорная память | Не начато; доступа к B200 нет |
| AMD CDNA: шаблон ping-pong, MFMA 32×32, `buffer_load … lds` | Не начато; будет замеряться на удалённом MI300X |
| AMD RDNA, Apple | Только атомы; ни таблиц, ни выпущенных ядер |
| Роли варпов, барьеры ролей, инструкции raw asm | Записываются в IR, отвергаются понижением |
| Свёртка (implicit GEMM) | Только CUDA sm_80+ (`ops::conv2d`); AMD остаётся на графе или tk1, пока нет таблиц, а модель YOLO ещё не подключена |
| Веса fp8/int8, GEMV + argmax, persistent grid, обратный проход внимания | Не начато |
