# 调优 {#tuning}

每个算子在 `ops::config` 中依据设备测得的代价为每种形状的配置排序（见[设备代价](#device-costs)），在已保留 16 个 tile（`config::KEPT_TILES`）之后，丢弃代价超过最便宜者 2.5 倍的配置（`config::PRUNED_PAST`）。排序是一个模型，寄存器计数也是，因此二者都不决定配置的准入。决定准入的是一条规则：调优器并行编译排序后的配置，直到按排序顺序得到前 56 个（`config::SHORTLIST`）编译后内核不溢出的 tile（内核报告了溢出的 scratch 字节即为溢出；什么都不报告的后端视为准入）。tile 以其第一条干净的流水线（环形缓冲深度、展开）被准入，因此会溢出的展开环形缓冲让位于其不展开的孪生配置。一条流水线只在其 tile 排在它之前的流水线溢出或编译失败时才被编译，第 56 个干净 tile 之后的一概不编译：恰是按排序逐个编译配置的遍历会编译的那些（`config::Search`）。没有任何流水线能干净编译的 tile 排在干净 tile 之后、仍在这 56 个之内，每个取一条流水线：编译后的内核判断它能判断的，其余交给计时（没有算子会因为溢出而退回计算图）。搜索一旦需要某个配置，就在线程池上开始编译它（线程池有空闲时，tile 的下一条流水线会在前一条仍在编译时提前开始，其结果只在逐个遍历本会请求它时才被采用）；编译器运行超过 30 s（`tune::COMPILE_TIMEOUT`）的会被终止，该配置如同编译失败一样被拒绝，规划器日志会注明（`compile timed out`）；降级后的程序发出的指令数超过其目标允许值（`Target::most_instructions`：AMD 上为 2^18，CUDA 上为 2^19，高于排序中最大的内核）的配置，会在任何编译器看到它之前被降级本身拒绝（`lower::Error::TooLarge`，规划器日志中的 `does not lower`），并同样被排除。每个程序在一次调优中只降级一次：存储指纹降级得到的程序就是编译所启动的内核体。

准入的配置连同其变体（注意力的键拆分、饥饿卷积的归约拆分、GEMM 的尾部拆分及其不拆分的流水线）就是调优存储在设备第一次遇到某个形状时测量的候选。随后，领先的各 tile 中处于领先者竞争区间之内的那些（至多八个，`config::TWIN_TILES`）的其余流水线被编译，并与胜者对比计时，无论是否溢出，最快者即为最终选择。注意力轮流调优其 softmax 形式和 tile（见[内核库](./kernel-library#flash-attention)）。当什么都无法编译时（没有可供编译的设备），直接使用前 56 个 tile 而不做测试。GEMM 的尾部拆分若其 f32 部分和（每次调用都与操作数一起分配）会占用超过设备内存的八分之一，则在其形状上被拒绝（`ShapeRejected::Partials`）。

关闭调优时不计时：运行排序列表中第一个编译干净的配置，按排序顺序每批八个编译直至找到，并以 `first` 行保存在存储中。设备的代价探针仍会测量，因为排序需要它们。

## 何时进行测量 {#when-measurement-happens}

算子在被调用的地方、即构建计算图时进行测量，从不在运行中的计划内部测量。每个候选被构建为程序，在按容量分配的临时缓冲区上启动，所有运行时变量都绑定到其最大值（浮点操作数填充从 `[-1, 1)` 中抽取的值，因此在真实数据下降频的显卡按其实际运行状态计时；整数操作数填充零），然后计时：

| 步骤 | 设置 |
|---|---|
| 预热 | 连续运行直到时钟稳定 |
| 轮次 | 先按排名顺序对所有候选跑一轮，首次计时运行超过当前最佳 2 倍的候选即以该次时间为准；再对竞争者跑 3 轮：即第一轮成绩在最佳值 1.2 倍以内的候选（候选不足 8 个时为 2 倍以内），第二轮之后只保留在当前最佳值 1.05 倍以内的候选，后续各轮交替按逆序和正序运行，使每个候选都在其前后两个邻居之后各运行一次；竞争者多于两个时，再对两名领先者跑 4 轮。一次调优的首次计时只用于挑选领先的 tile，在第二轮后结束：这些 tile 会连同其其余流水线再次计时 |
| 每轮 | 5 ms 设备时间的连续维持运行，按顺序运行候选的各个程序（至多 1024 次启动，按该候选上一次运行的时长计算），然后对每个程序做剖析运行直到其最小值稳定，保留每个候选的最小值：至少为 20 ms 设备时间所能容纳的次数，2 到 5 次（`tune::runs`；领先者的轮次和代价探针为 5 次），之后持续运行，直到连续三次都在最小值的 97 % 以内，最多 24 次；在领先者的轮次之外，耗时 5 ms 及以上的候选既不做维持运行也不再多运行：其第一次计时运行即为该轮的时间 |
| 一次运行的时间 | 其各内核 GPU 时间戳之和 |

维持运行按设备时间计量，因为启动是异步排队的。一个候选是一组程序：对拆分而言是一个内核加上合并其部分结果的内核，其时间是各程序时间之和，再为第一次之后的每次启动加上 `config::LAUNCH`（`tune::launched`）：两个内核之间的间隙，设备时间戳看不到它。计时开始时尚未编译的候选（拆分的变体、tile 的孪生配置）在线程池除一个线程外的所有线程上编译，同时对已就绪的候选计时，每个候选在排序顺序轮到它时计时。构建或运行失败的候选被跳过。如果什么都没测到，就使用第一个候选，并且不存储任何内容。

有两道防护保证计时可信：

- **一把设备锁。** 进程中的每次计时，无论是调优器的还是代价探针的，都持有同一把锁：共享设备的两次测量会互相干扰计时。两个线程调优同一个键时只测量一次；第二个线程等待第一个的结果。
- **时间戳防护。** 低于该候选运行中位数一半的运行被视为丢失的时间戳，在保留最快值之前被丢弃，调优器和探针都是如此。

## 存储 {#the-store}

| 项目 | 值 |
|---|---|
| 目录 | `$SVOD_TK_TUNE_DIR`，否则 `$XDG_CACHE_HOME/svod/tk_tune`，否则 `~/.cache/svod/tk_tune` |
| 文件 | 每个设备和 crate 版本一个，例如 `sm_86_28sm-v<crate 版本>.txt`，以其行格式作为首行（`format 11`）；其他格式或没有该行的文件整个丢弃 |
| 行 | `kind\|op\|device\|dtype\|shape\|candidates\|compiler\|programs numbers`：`choice` 存放运行过的候选，最快者在前，每个为 `index:code ns`，`code` 是配置自身的文本，因此一行无需其排序即可重放（程序发射结果与另一候选相同的候选——比如被调度折叠掉的反滚——按其孪生的 ns 记录，两者共用同一内核）；`value` 存放一个测得的数；`admitted` 存放准入保留的每个配置的 `index:code`；`first` 存放第一个干净配置的 `index:code` |
| 键 | `tune::TuneKey { op, device, dtype, shape, candidates, compiler }`，其中 `device` 是架构和 SM 数量（`sm_86-28sm`），`compiler` 是设备编译器的摘要（`tune::compiler`） |

GEMM 选择行（形状 `[batch, m, n, k]`，其编码以光栅顺序和尾部拆分结尾，`~` 表示无拆分）和代价探针值行（每单位飞秒）的形式；摘要和数值为占位符：

```text
choice|linear|sm_86-28sm|BFloat16|1x4096x4096x4096|<candidates>|<compiler>|<programs> 0:w,128,256,64,2,4,r3u,g8,~ <ns> 3:w,128,128,32,2,2,r3u,g8,~ <ns>
value|probe:cached_1m|sm_86-28sm|Int32||<candidates>|<compiler>|<programs> <fs>
```

`programs` 字段是候选所发射内核的指纹：降级后的程序以及交给后端的 LLVM 文本，因此对内核或渲染器的改动会触发重新测量，而发射出相同内核的重构不会。一个程序发射什么，按其组成内容、按可执行文件的每次构建记录在存储根目录下的 `emitted/<build>.txt` 中（一周未用的构建会被删除），因此同一构建的热进程无需降级任何东西，而重新构建后每个程序降级一次。只有存储未命中时才编译。写入时会重新读取、合并并原子地替换文件。无法读取或写入的存储视为未命中，从不报错。

## 设备代价 {#device-costs}

排序所用的代价（`atoms::Costs`：一个共享字节、一个流式字节、一个分散元素、满载 SM 上的一步矩阵核运算，以及在 SIMD 上单独一个 wave、作为 warpgroup 乘积、在宽核心上和针对 8 位整数（满载与单独）时的一步、一个分数的 softmax、一次流水线行程（环的两个槽位，展开与不展开，以及一个槽位）、SM 上只有一个块时两个槽位和一个槽位的行程、一次 lane 移动、一次共享内存往返、经环的两个槽位（以及在 `cp.async` 填充的目标上经一个槽位）的全局延迟，以及缓存阶梯：各工作集大小下流式字节的代价，L2 的速率和容量由它读出）由 `probe::costs` 在进程第一次为该设备做规划时在设备上测量。每个字段是一对程序，其中探针做其基线所做的一切，再加上已知数量的该原语。这些值以 `value|probe:<field>` 行写入同一个存储文件，因此之后的进程会读回它们。失败的探针让其字段保持为零，发出警告，并在 `Planner::unmeasured` 中列出，而设备门控 `device_costs_are_physical` 要求该列表为空：规划器用已有的数据排序，而不是把设备丢给计算图。只有没有 SM 数量的设备才没有规划器。驻留由目标声明的内容而非探针定价：一个 SM 同时容纳的块数是其共享内存、寄存器和 wave 槽能容纳的数量，且至多为 `Occupancy::blocks`，即不论资源如何的硬件上限。

主机测试则直接声明代价：猜测的夹具 `costs()`，以及 `test/unit/mod.rs` 中的 `sm86_costs()`、`gfx1201_costs()`、`gfx942_costs()` 和 `gfx1151_costs()`，各自取自对应设备的探针。对于本机没有对应设备的显卡，`Target::offline` 或 `Target::card` 给出目标，`probe::stored` 从该卡上拷贝来的调优存储中读取代价；没有这样的存储时，以 `probe::GUESSED` 代替，排序也就只是猜测。[`tk_dump` 示例](./testing-and-debugging#planning-for-another-card)两者都做。

## 规划器日志 {#the-planner-log}

`RUST_LOG=svod_tk::plan=debug` 记录规划器的决策：哪个算子走了计算图及其原因；排序的前 16 个配置及其预测的 ns，以及它略去了多少配置；存储未命中时，编译每个配置的结果（结论、寄存器数、溢出字节数）；以及调优后的选择。`RUST_LOG=svod_tk=debug` 还会加上调优器的各轮计时。

## 关闭调优 {#switching-it-off}

| 方式 | 作用 |
|---|---|
| `SVOD_TK_TUNE=0` | 关闭候选计时；运行排序中第一个编译干净的配置（以 `first` 行保存）；代价探针仍会测量 |
| `svod_tk::tune::scoped(false, f)` | 在当前线程（及其用于编译的工作线程）上对 `f` 效果相同，优先于环境变量；测试中使用 |

`tune::TuneStore::at(root)` 在另一个根目录构建存储，传入 `None` 时仅存在于内存中。

## 基准测试 {#benchmarks}

`tk_bench` 示例在默认设备（`SVOD_DEVICE`）上为 tk 的内核计时。每个配置的时间是时钟升频之后它最快的一次 profiling 运行，即其各内核设备时间戳之和；同一形状的各配置轮流计时，使漂移对每个配置的影响相同。它只打印，从不断言。在空闲的 GPU 上一次运行一个命令：

```bash
SVOD_DEVICE=CUDA cargo run --release -p svod-tk --example tk_bench -- gemm --top 8
```

| 命令 | 输出 |
|---|---|
| `gemm [--shape MxNxK,…] [--top N]` | 调优器选择（默认 4096³）的 bf16 GEMM TFLOP/s，并加以标记，以及规划器排名前 `N` 的配置的 TFLOP/s |
| `attention [--shape BxHxTxD,…] [--causal] [--bias] [--top N]` | 算子实际启动的内核以及排名前 `N` 的配置的 Flash attention TFLOP/s；默认 B 4、H 8、T 2048，d 64（普通、因果、带偏置、两者皆有）和 d 128（普通、因果） |
| `nearest [--rows N] [--depths D,…] [--k K] [--metric M]` | 经 nearest 算子的一次自连接，以 Gpairs/s 和 TFLOP/s 计；默认 65536 行、深度 16 到 128：平方距离、64 个分组下的同一计算、高于两侧下限的 L2 |
| `rerank [--rows N] [--candidates M] [--depths D,…] [--ks K,…] [--metric M]` | 分别以 8 位和 f16 搜索的 `k_nearest_reranked`，与普通 f16 `k_nearest` 对比 |
| `raster [--shape MxNxK,…]` | 调优器的 GEMM 选择和规划器第一个配置的每种光栅顺序，与默认顺序对比，并列出代价模型对每种顺序的估价 |
| `fit [--only LABEL,…] [--picks]` | 代价模型与设备的对比：若干 GEMM、注意力和 nearest 形状上每个排名配置的预测时间与实测时间、调优器的选择及调优器的墙钟时间；`--picks` 只为选择计时 |
| `trips` | 每个 SM 驻留 1 到 48 个块时的流水线迭代探针 |
| `pin --cfg BMxBNxBK:S:WRxWC[:rolled],… [--shape MxNxK,…] [--residual] [--gated]` | 每个固定的 GEMM 配置的时间（默认为 Whisper 的 fc2），旁边是模型的价格，以及分别将内存延迟、单独行程或矩阵核步骤置零后的价格：每一项占该配置时间的多少 |

`--metric` 可取 `squared-l2`、`l2` 或 `neg-dot`。每个命令都按调优器的方式计时：一个配置的所有内核一起计时（拆分的合并、尾部的部分和），算子的计划也一样。
