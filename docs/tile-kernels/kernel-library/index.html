Kernel Library

Every kernel in svod_tk::kernels is a function from a spec to a Program, generic over the 16-bit element type (BF16 or F16); gemm and nearest also take 8-bit integers (I8, accumulated exactly in i32: gemm stores f32, nearest scales each row's products by the rows' x_scale and c_scale).

Where the planner picks a kernel's config (gemm, conv, attention, nearest), the spec (GemmSpec, ConvSpec, AttnSpec, NearestSpec) is a plain description of shapes and options, and the kernel takes it admitted under its config: fn k<T>(spec: &Admitted) -> Program. spec.admitted(&planner, cfg) returns one where the planner admits cfg for that very spec (the config feasible on the target for the problem the spec states, claimed on its shape), or the reason it does not; the unsafe Admitted::assume(spec, cfg) takes a config without admission and checks nothing. An admitted spec is read-only: it derefs to the spec, and cfg() returns the config. The other kernels (heads, norm, combine, split_merge and the nearest search's select, merge and rescore) take their spec as it is, its config inside.

GemmSpec, ConvSpec, AttnSpec, HeadsSpec and NormSpec have a batch: Batch: Batch::Static(n) launches n batches, and Batch::var(name, min, max) (an ir::Var) launches the live count of a runtime variable bound by name, with buffers sized for max. GemmCfg and FaCfg have a lowering(&device) (an atoms::Device: the target and its costs); the other kernels lower with Lowering::new(&device). Models reach these kernels through the op layer, which picks the config.

GEMM​

c = scale·act(a·bᵀ + bias) + residual, with a [batch·m, k] and b [n, k]. Everything after the matrix product runs on the f32 accumulator, and the result is rounded once at the store.

Epilogue fieldEffect
bias[n] row added to the accumulator ([2n] when gated)
actAct::None, Act::Gelu (erf approximation, error at most 1.5e-7), Act::Silu
gatedb is [2n, k], gate rows over up rows; output act(gate)·up (SwiGLU, GeGLU)
scaleMultiplies the activated value before the residual
residual[batch·m, n] added last
out_f32f32 output and residual, the accumulator stored unrounded
ropeRope { heads, head_dim, seq }: the first heads heads of head_dim columns rotated by [seq, head_dim/2] cos and sin tables (output row m at position m % seq), the columns after them stored as they are; with a bias alone, on a tile whose warps hold whole heads (GemmCfg::turns)

GemmCfg { tile: [bm, bn, bk], warps: [rows, cols], core, schedule, order, tail }. Rows past m and columns past n are bounded views, so m and n are free. k must be a multiple of bk. core: Core::Group issues the products on wgmma (sm_90); schedule: Schedule::ping_pong(k) runs the two warp rows in ping-pong over one slot (CDNA). The blocks walk the output tiles in groups of order tile rows (gemm::TileOrder, 8 by default, TileOrder::DEFAULT; one row is row-major, the grid's rows column-major), so blocks resident together read the same B tiles. The planner plans every config at the default; a config may carry another group height (the g field of its code).

The rotation reads each element's partner half a head along through a column flip. When a warp's columns hold whole heads, a lane holds both halves, and the flip is a register renaming. The tables are read through a periodic view, so every head of a row reads the same [head_dim/2] row. The turn is not free in the ranking: its operations and the tables' reads are claimed beside the epilogue's, and a tile that holds no whole heads is refused.

tail (gemm::TailSplit, up to config::TAIL_SPLITS ways) splits the tiles of a partial last wave along K: the whole waves run data-parallel, the tail writes f32 partials, and split_merge applies the epilogue. The planner prices each split with a launch cost (config::LAUNCH) for every launch past the first, and refuses one whose partials outgrow an eighth of device memory (ShapeRejected::Partials); the tuner times a leading split beside its unsplit pipeline. Batched, gated, rotating and convolution GEMMs take none.

There is no tile table. config::Planner::gemm_ranked enumerates tiles, bk, warp grids, ring depths and unrolling, keeps what the lowering runs on the target (the atoms tile the warp grid, the fills split into whole 16-byte chunks per thread, the ring fits shared memory) and ranks the rest in nanoseconds of SM time from the device's measured Costs. Every device input to the ranking is measured; its model constants (BAND, OVERLAP_WAVES, LAUNCH and each family's operation weights, each marked Model: in ops::config) are meant to hold for every device, and fill bytes are priced from the measured cache ladder. A GEMM's output is priced at its type's bytes, with its residual and bias reads. The ranking orders, and the tuner measures the first 56 tiles (config::SHORTLIST) that compile without spilling (Tuning).

Convolution​

conv::conv is an implicit GEMM over channels-last x [b, h, w, cin] and w [cout, kh, kw, cin]: A is a row-mapped view of the image (conv::im2col_view), so padding rows read zero and nothing is materialized. K = kh·kw·cin runs as one pipeline, each step inside one tap (bk divides cin). On a starved grid of a single static batch, ConvCfg::split (a ConvSpec's split) splits K over grid z and gemm::split_merge applies the epilogue. ops::conv2d takes a 1×1 as linear and keeps groups ≠ 1, cin off 16 and cout off 8 on the graph.

Flash attention​

o = softmax(q·kᵀ·scale + bias)·v over sequence-major q [batch, t, heads, d] and k, v [batch, tk, kv_heads, d]. Q stays in registers and K/V stream through a shared ring. The online-softmax state (m, l, o) is carried in f32 using exp2.

FeatureHow
GQAQuery head h reads KV head h / (heads / kv_heads)
Cross attentiontk ≠ t is a property of the views
Any t, tkBounds instead of padding: the query tile and the last key block are bounded views, and keys past tk are masked
Head dimsAny d both products tile, whose fills split into whole chunks per thread (FaCfg::fits); the models use 48, 64 and 128
AttnMask::causalKey blocks past the diagonal are skipped through the trip count
AttnMask::window(left, right) around each query; blocks outside are skipped
AttnMask::chunkBlock attention: a query sees its chunk, left chunks before (all, without a bound) and right after
AttnMask::key_lens[batch] i32 valid key counts; blocks past the length are skipped
AttnMask::key_mask[batch, tk] i32 visible keys (row stride rounded up to 8), read in every block
AttnMask::seg_start[batch, t] i32 segment starts of packed rows, non-decreasing along t
AttnMask::bias[batch or 1, heads, t, tk] additive bias in the stream type (row stride rounded up to 8), added to the scaled scores before the masks

Only key blocks that a causal, window, chunk, length or segment edge crosses compute the predicate; blocks fully inside run unmasked. A key mask and a bias are read in every block. A query that sees no key yields zeros, as the graph writes it.

Cache mode (AttnSpec::cache = Some(CacheLayout { .. })) reads K and V from a cache [rows, tk, heads_total, d] that holds several layers' heads:

CacheLayout fieldEffect
rows, heads_totalThe cache's shape
row_mapA [batch] i32 parameter: the cache row each batch lane reads
appendedRows of [batch, appended, kv_heads, d] keys and values scored after the cached prefix (the tokens a decoder step just projected), at most a key block; 0 appends nothing
app_lensA [batch] i32 parameter of visible appended rows

The first of this attention's heads is a [1] i32 head_start parameter, so every layer runs one program.

Packed mode (AttnSpec::packed) reads q, k and v from one [batch, t, heads + 2·kv_heads, d] parameter, a fused projection, at head offsets 0, heads and heads + kv_heads, without a cache. The kernel is flash_attention_packed, tuned apart from the one of separate operands; on the same config both compute the same bits.

Key splits (FaCfg::splits > 1) give a few long rows, such as a decoder step, more blocks. Each split writes f32 partials o_part, m_part and l_part, and combine merges them. Attn::splits = Some(n) fixes the count; with None, Planner::splits proposes 1, 2, the counts around two blocks per SM and one split per key block, and the tuner times each split candidate together with its merge.

FaCfg { bq, bkv, schedule, splits, forms, key_warps, warp_rows, core }:

FieldEffect
warp_rowsQuery rows per warp: 16 (one atom row) or 32 (each K and V fragment feeds two atom rows); the 32-row form is a variant the tuner times beside its 16-row tile
key_warpsA one-row-warp block (bq = 16, offered for t ≤ 16) splits its key blocks over 1, 2 or 4 warps, each with its own ring slots and softmax state, merged through shared memory
coreCore::Wide runs both products on CDNA's 32×32×8 MFMA; Core::Group on wgmma (sm_90)
formsThe softmax forms below

Candidates come from the same lattice and cost model as the GEMM's (Planner::attention_ranked). Where the fill goes through registers, the value tile is stored column-major so its fragments gather as 16-byte loads; on RDNA4 the fill itself is a transposing load (global_load_tr_b128).

The softmax adopts a new running maximum only when it grows by more than 8 in log2 units (FlashAttention-4's lazy rescale). Five Forms are tuner knobs, all off as planned; the tuner flips each where it measures faster (a forms pass, then the tiles under those forms, then the forms again on the winner):

Forms fieldEffect
truncate_pbf16 probabilities are truncated rather than rounded, and the row sum adds what is held
sum_afterThe row sum follows the P·V product rather than preceding the rescale
skip_rescaleThe output's rescale is a Scale, skipped by every wave whose rows all kept their maximum
raw_maxThe running maximum stays in the raw scores' units: a multiply per row rather than per score
bias_directEach key block's bias tile is read from global memory in the scores' layout rather than through a ring slot

Attention prologue​

heads splits a fused projection qkv [batch, t, (heads + 2·kv_heads)·d] into sequence-major q [batch, t, heads, d] and k, v [batch, t, kv_heads, d]. Optionally it RMS-normalizes q and k over the head with [d] weights, then applies rotary embedding to them. The rotation pairs the head's two halves, using (cos, sin) tables of [t, d/2], shared or per batch (Rope { per_batch }). A block handles br rows of one head slot. d must be a power of two in 16..=256, and candidates are br ∈ {4, 8, 16}.

Norms​

rows::norm uses one warp per row and a fused reduce-then-map in f32:

NormFormula
Layer(x − mean)·rsqrt(var + eps)·w + b
Rmsx·rsqrt(mean(x²) + eps)·w

With residual: true it normalizes x + residual rounded to the element type and also writes that sum, which is the pre-norm residual stream of a transformer layer. d must be a multiple of 256 in 256..=2048, and candidates are br ∈ {4, 8, 16} rows per block.

Nearest-neighbour search​

nearest::nearest scores the rows of x [n, d] against the candidates c [m, d] under a Metric (SquaredL2, ShiftedL2, L2, NegDot) and keeps each row's k least scores, ascending, with their indices. NearestSpec { n, m, d, dtype, metric, floors, groups, k, live } states its element type (dtype: a 16-bit float or 8-bit integers), and the kernel runs over that type alone. NearestCfg::list (nearest::Way) says where a row's k least are kept:

WayList
RegistersAll k in a register list
Queued(Pow2)A register queue of that many scores (from 2, below k), merged into the rest of the list held in the outputs
Matrix(SelectCfg)The scores stored as a matrix, whose rows nearest_select lists

Pow2 holds a power of two, so a queue, and the width and depth of a list's lane queues (LaneQueue), are powers of two by construction. Split (NearestCfg::splits > 1), the blocks of a query block each fold a share of the candidates and nearest_merge merges the shares' lists. k_nearest_reranked searches over 8-bit or 16-bit rows and scores the candidates it keeps again in f32 with nearest_rescore.
