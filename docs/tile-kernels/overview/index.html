Tile Kernels (tk)

Svod's optimizer finds fast schedules for most of a model by searching over loop transformations. Some kernels cannot be found that way. Flash attention is a recurrence: every key block updates a running maximum and sum and rescales the accumulator, so there is no single reduction to tile. A fast GEMM on a tensor-core GPU depends on a multi-stage cp.async ring, ldmatrix fragment loads and a swizzled shared layout, which are not steps of a loop search. Kernels like these are written by hand, and svod-tk ("tk") is the crate for writing them.

svod-tk implements the third version of the tile language ("tk3") and is the only tile-kernel crate. It replaced tk1, the earlier crate of the same name, which was removed together with its k-means, kNN and Apple kernels; none of them was ported. Eight models run on the op layer: Nemotron-3-Diarization, Whisper (the encoder, and the decoder step's attention in cache mode), ModernBERT, BGE-M3/XLM-RoBERTa, Qwen3-Embedding, GigaAM, WavLM and YOLO26 (channels-last, its 3×3 convolutions on ops::conv2d).

What tk is​

PieceModuleWhat it does
Tile programir, buildA structured statement tree (Let, Copy, Loop, Pipeline, If, Warps) over tile values, recorded by a Kernel builder in program order. It is not a DAG.
Layoutslayout, layoutsF2 linear layouts (bit matrices) for every fragment and swizzle, assigned by inference. Kernel code never names a lane.
AtomsatomsPer-target matrix-core instructions with their operand layouts: mma.sync (CUDA), wgmma (sm_90), WMMA (RDNA3/3.5/4), MFMA 16×16×16 (CDNA).
Schedule templatesscheduleExpand a Pipeline into cp.async groups, a register-staged ring of one or two slots, or two crews in ping-pong (CDNA GEMM). The author writes only the produce and consume bodies.
LoweringlowerInserts barriers from effects, expands the schedule, infers layouts and emits a pre-linearized instruction list (Op::Linear), so no toposort decides the order.
KernelskernelsGEMM with epilogues, implicit-GEMM 3×3 convolution with split-K, flash attention, the attention prologue, LayerNorm/RMSNorm. Each is a spec struct in and a Program out.
LaunchlaunchRuns a program as a custom kernel in the lazy graph, with lowered bodies memoized.
Op layeropslinear, conv2d, attention, heads, layer_norm, rms_norm, … These always return a Tensor, using a kernel when one fits and the graph otherwise.
Plannerops::configRanks each shape's configs from the device's measured costs.
InterpreterinterpRuns any tile program on the host to give reference numerics without a GPU.
Tune storetuneMeasures each op's candidates once per shape and device and keeps the winner on disk.

On the RTX 3060, RMSNorm over 8192×1024 bf16 moves 325 GB/s of the card's 360, and Nemotron-3-Diarization (bf16, four steps) takes 45.82 ms of GPU time in 1064 dispatches, against 2292 dispatches before tk3.

Not in this release

Hopper TMA and mbarrier producers (sm_90 runs wgmma fed by cp.async), Blackwell tcgen05, 32×32 MFMA, Apple kernels, fp8, int8 beyond the nearest-neighbour search, attention backward, and the convolution's image-staged form. See Portability.
