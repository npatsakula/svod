कर्नेल लाइब्रेरी

svod_tk::kernels का हर कर्नेल एक function fn k<T: Elem>(spec: &Spec) -> Program है, जो 16-bit element type (BF16 या F16) पर generic है; gemm और nearest 8-bit integers (I8) भी लेते हैं, जो i32 में exact रूप से accumulate होते हैं: gemm f32 store करता है, और nearest हर row के products को rows के x_scale और c_scale से scale करता है। हर spec में एक batch: Batch होता है: Batch::Static(n) n batches launch करता है, और Batch::var(name, min, max) (an ir::Var) नाम से bind हुए runtime variable की live गिनती launch करता है, buffers max के आकार के होते हैं। हर config type में एक lowering(&device) है (एक atoms::Device: target और उसकी costs)। मॉडल इन कर्नेलों तक op layer के ज़रिए पहुँचते हैं, जो config चुनती है।

GEMM​

c = scale·act(a·bᵀ + bias) + residual, जहाँ a [batch·m, k] और b [n, k]। Matrix product के बाद का सब कुछ f32 accumulator पर चलता है, और नतीजा store पर एक बार round होता है।

Epilogue fieldअसर
biasaccumulator में जोड़ी गई [n] row (gated होने पर [2n])
actAct::None, Act::Gelu (erf approximation, error अधिकतम 1.5e-7), Act::Silu
gatedb [2n, k] है, gate rows ऊपर, up rows नीचे; output act(gate)·up (SwiGLU, GeGLU)
scaleresidual से पहले activated value को गुणा करता है
residual[batch·m, n], सबसे आख़िर में जोड़ा जाता है
out_f32f32 output और residual; accumulator बिना round किए store होता है

GemmCfg { tile: [bm, bn, bk], stages, warps: [rows, cols], unroll, core, crews }। m से आगे की rows और n से आगे के columns bounded views हैं, इसलिए m और n मुक्त हैं। k का bk का गुणज होना ज़रूरी है। core: Core::Group products को wgmma (sm_90) पर issue करता है; crews: 2 दोनों warp rows को एक slot पर ping-pong में चलाता है (CDNA)। Blocks output tiles पर 8 tile rows (gemm::GROUP_ROWS) के समूहों में चलते हैं, ताकि एक साथ resident blocks वही B tiles पढ़ें।

कोई tile table नहीं है। config::Planner::gemm_ranked tiles, bk, warp grids, ring depths और unrolling गिनता है, वही रखता है जिसे lowering target पर चलाती है (atoms warp grid को tile करते हैं, fills हर thread पर पूरे 16-byte chunks में बँटते हैं, ring shared memory में समाती है) और बाक़ी को device की मापी गई Costs से SM time के nanoseconds में rank करता है। Ranking का हर device input मापा गया है; उसके गिने-चुने model constants (ops::config में BAND, CACHE_SHARE, CACHE_SPILL, OVERLAP_WAVES) हर device पर लागू होने के लिए हैं। Ranking क्रम देती है, और tuner उन पहले 64 tiles को मापता है जो बिना spill के compile होते हैं (Tuning)।

Convolution​

conv::conv channels-last x [b, h, w, cin] और w [cout, kh, kw, cin] पर एक implicit GEMM है: A image का row-mapped view है (conv::im2col_view), इसलिए padding rows शून्य पढ़ी जाती हैं और कुछ भी materialize नहीं होता। K = kh·kw·cin एक pipeline के रूप में चलता है, हर step एक tap के भीतर (bk cin को भाग देता है)। एक ही static batch के भूखे grid पर ConvCfg::split K को grid z पर बाँटता है और gemm::split_merge epilogue लागू करता है। ops::conv2d 1×1 को linear के रूप में लेता है, और groups ≠ 1, 16 पर न बैठने वाले cin और 8 पर न बैठने वाले cout को ग्राफ़ पर रखता है।

Flash attention​

Sequence-major q [batch, t, heads, d] और k, v [batch, tk, kv_heads, d] पर o = softmax(q·kᵀ·scale + bias)·v। Q registers में रहता है और K/V एक shared ring से stream होते हैं। Online-softmax state (m, l, o) exp2 के सहारे f32 में carry होती है।

Featureकैसे
GQAQuery head h KV head h / (heads / kv_heads) पढ़ता है
Cross attentiontk ≠ t views का गुण है
कोई भी t, tkPadding की जगह bounds: query tile और आख़िरी key block bounded views हैं, और tk से आगे की keys masked हैं
Head dimsकोई भी d जिसे दोनों products tile करें और जिसकी fills हर thread पर पूरे chunks में बँटें (FaCfg::fits); मॉडल 48, 64 और 128 इस्तेमाल करते हैं
AttnMask::causalDiagonal से आगे के key blocks trip count के ज़रिए छोड़ दिए जाते हैं
AttnMask::windowहर query के आसपास (left, right); बाहर के blocks छोड़ दिए जाते हैं
AttnMask::chunkBlock attention: query अपना chunk देखती है, उससे पहले left chunks (bound न हो तो सभी) और बाद में right
AttnMask::key_lens[batch] i32 वैध key counts; length से आगे के blocks छोड़ दिए जाते हैं
AttnMask::key_mask[batch, tk] i32 दिखने वाली keys (row stride 8 तक ऊपर round), हर block में पढ़ी जाती है
AttnMask::seg_startpacked rows के [batch, t] i32 segment starts, t के साथ non-decreasing
AttnMask::biasstream type में [batch or 1, heads, t, tk] additive bias (row stride 8 तक ऊपर round), masks से पहले scaled scores में जोड़ा जाता है

सिर्फ़ वे key blocks predicate की गणना करते हैं जिन्हें कोई causal, window, chunk, length या segment किनारा काटता है; पूरी तरह भीतर के blocks बिना mask के चलते हैं। Key mask और bias हर block में पढ़े जाते हैं। जो query कोई key नहीं देखती वह शून्य देती है, जैसा ग्राफ़ लिखता है।

Cache mode (AttnSpec::cache = Some(Cache { .. })) K और V को एक cache [rows, tk, heads_total, d] से पढ़ता है जिसमें कई layers के heads होते हैं:

Cache fieldअसर
rows, heads_totalCache का shape
row_mapएक [batch] i32 parameter: हर batch lane कौन सी cache row पढ़ती है
appended[batch, appended, kv_heads, d] keys और values की rows जो cached prefix के बाद score होती हैं (वे tokens जिन्हें decoder step ने अभी project किया), अधिकतम एक key block
app_lensदिखने वाली appended rows का एक [batch] i32 parameter

इस attention के heads में से पहला एक [1] i32 head_start parameter है, इसलिए हर layer एक ही program चलाती है।

Key splits (FaCfg::splits > 1) कुछ लंबी rows, जैसे decoder step, को ज़्यादा blocks देते हैं। हर split f32 partials o_part, m_part और l_part लिखता है, और combine उन्हें मिलाता है। Attn::splits = Some(n) गिनती तय करता है; None होने पर Planner::splits 1, 2, हर SM पर दो blocks के आसपास की गिनतियाँ और हर key block पर एक split प्रस्तावित करता है, और tuner हर split candidate को उसके merge के साथ मापता है।

FaCfg { bq, bkv, stages, splits, unroll, forms, key_warps, warp_rows, core }:

Fieldअसर
warp_rowsहर warp की query rows: 16 (एक atom row) या 32 (हर K और V fragment दो atom rows को खिलाता है); 32-row रूप एक variant है जिसे tuner उसके 16-row tile के साथ मापता है
key_warpsएक-row-warp block (bq = 16, t ≤ 16 के लिए पेश) अपने key blocks को 1, 2 या 4 warps पर बाँटता है, हर एक के अपने ring slots और softmax state के साथ, जो shared memory के ज़रिए मिलाए जाते हैं
coreCore::Group दोनों products को wgmma (sm_90) पर चलाता है
formsनीचे के softmax forms

Candidates GEMM वाली उसी lattice और cost model से आते हैं (Planner::attention_ranked)। जहाँ fill registers से होकर जाता है, वहाँ value tile column-major store होता है ताकि उसके fragments 16-byte loads के रूप में gather हों; RDNA4 पर fill ख़ुद एक transposing load (global_load_tr_b128) है।

Softmax नया running maximum तभी अपनाता है जब वह log2 units में 8 से ज़्यादा बढ़े (FlashAttention-4 का lazy rescale)। पाँच Forms tuner knobs हैं, plan में सभी बंद; tuner हर एक को वहाँ चालू करता है जहाँ वह तेज़ मापता है (एक forms pass, फिर उन forms के तहत tiles, फिर विजेता पर forms दोबारा):

Forms fieldअसर
truncate_pbf16 probabilities round होने के बजाय truncate होती हैं, और row sum वही जोड़ता है जो रखा है
sum_afterRow sum rescale से पहले के बजाय P·V product के बाद आता है
skip_rescaleOutput का rescale एक Scale है, जिसे हर वह wave छोड़ देती है जिसकी सभी rows ने अपना maximum बनाए रखा
raw_maxRunning maximum raw scores की units में रहता है: हर score के बजाय हर row पर एक गुणा
bias_directहर key block का bias tile ring slot के बजाय सीधे global memory से scores के layout में पढ़ा जाता है

Attention prologue​

heads एक fused projection qkv [batch, t, (heads + 2·kv_heads)·d] को sequence-major q [batch, t, heads, d] और k, v [batch, t, kv_heads, d] में बाँटता है। वैकल्पिक रूप से यह q और k को head पर [d] weights के साथ RMS-normalize करता है, फिर उन पर rotary embedding लागू करता है। Rotation head के दो हिस्सों को जोड़ी बनाता है, [t, d/2] की (cos, sin) tables इस्तेमाल करते हुए, जो साझा या हर batch की अलग होती हैं (Rope { per_batch })। एक block एक head slot की br rows संभालता है। d का 16..=256 में दो की घात होना ज़रूरी है, और candidates br ∈ {4, 8, 16} हैं।

Norms​

rows::norm हर row पर एक warp और f32 में एक fused reduce-then-map इस्तेमाल करता है:

Normसूत्र
Layer(x − mean)·rsqrt(var + eps)·w + b
Rmsx·rsqrt(mean(x²) + eps)·w

residual: true के साथ यह element type में round किए गए x + residual को normalize करता है और वह sum भी लिखता है, जो transformer layer की pre-norm residual stream है। d का 256..=2048 में दो की घात होना ज़रूरी है, और candidates हर block में br ∈ {4, 8, 16} rows हैं।
