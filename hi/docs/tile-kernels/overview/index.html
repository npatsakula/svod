Tile कर्नेल (tk)

Svod का ऑप्टिमाइज़र किसी मॉडल के ज़्यादातर हिस्से के लिए तेज़ schedules loop transformations पर सर्च करके खोज लेता है। कुछ कर्नेल इस तरह नहीं मिलते। Flash attention एक recurrence है: keys का हर block एक running maximum और sum को अपडेट करता है और accumulator को rescale करता है, इसलिए tile करने के लिए कोई एक reduction है ही नहीं। Tensor-core GPU पर तेज़ GEMM एक multi-stage cp.async ring, ldmatrix fragment loads और swizzled shared layout पर टिका होता है, और ये loop search के कदम नहीं हैं। ऐसे कर्नेल हाथ से लिखे जाते हैं, और svod-tk ("tk") उन्हें लिखने का crate है।

svod-tk tile language का तीसरा संस्करण ("tk3") लागू करता है और एकमात्र tile-kernel crate है। इसने tk1 की जगह ली, जो इसी नाम का पुराना crate था और जिसे उसके k-means, kNN और Apple कर्नेल के साथ हटा दिया गया; इनमें से किसी को port नहीं किया गया। आठ मॉडल op layer पर चलते हैं: Nemotron-3-Diarization, Whisper (encoder, और cache mode में decoder step का attention), ModernBERT, BGE-M3/XLM-RoBERTa, Qwen3-Embedding, GigaAM, WavLM और YOLO26 (channels-last, जिसके 3×3 convolutions ops::conv2d पर चलते हैं)।

tk क्या है​

हिस्सामॉड्यूलक्या करता है
Tile programir, buildtile values पर एक structured statement tree (Let, Copy, Loop, Pipeline, If, Warps), जिसे एक Kernel builder program order में रिकॉर्ड करता है। यह DAG नहीं है।
Layoutslayout, layoutsहर fragment और swizzle के लिए F2 linear layouts (bit matrices), जिन्हें inference तय करता है। Kernel code कभी किसी lane का नाम नहीं लेता।
Atomsatomsहर target के matrix-core instructions अपने operand layouts के साथ: mma.sync (CUDA), wgmma (sm_90), WMMA (RDNA3/3.5/4), MFMA 16×16×16 (CDNA)।
Schedule templatesscheduleएक Pipeline को cp.async groups, एक या दो slots वाली register-staged ring, या ping-pong में दो crews (CDNA GEMM) में फैलाते हैं। लेखक सिर्फ़ produce और consume bodies लिखता है।
LoweringlowerEffects से barriers डालता है, schedule को फैलाता है, layouts infer करता है और एक pre-linearized instruction list (Op::Linear) emit करता है, ताकि क्रम कोई toposort तय न करे।
KernelskernelsEpilogues वाला GEMM, split-K के साथ implicit-GEMM 3×3 convolution, flash attention, attention prologue, LayerNorm/RMSNorm। हर एक में spec struct जाता है और Program निकलता है।
Launchlaunchकिसी program को lazy ग्राफ़ में custom kernel की तरह चलाता है, lowered bodies को memoize करते हुए।
Op layeropslinear, conv2d, attention, heads, layer_norm, rms_norm, … ये हमेशा एक Tensor लौटाते हैं: kernel फ़िट हो तो kernel, वरना ग्राफ़।
Plannerops::configहर shape के configs को device की मापी गई costs से रैंक करता है।
Interpreterinterpकिसी भी tile program को host पर चलाकर बिना GPU के reference numerics देता है।
Tune storetuneहर op के candidates को हर shape और device पर एक बार मापता है और विजेता को डिस्क पर रखता है।
model code ──► svod_tk::ops          always a Tensor; picks a kernel and config or builds the graph op
                   │
                   ▼
              kernels::*               spec ─► tile Program (builder, program order)
                   │
                   ▼
              lower::lower             operand loads ─► barriers ─► schedule template
                   │                   ─► layout inference ─► emission
                   ▼
              Op::Linear program  ──►  custom kernel in the lazy graph ─► LLVM ─► device

हर आँकड़ा उस कार्ड पर tuner का चुनाव है, जिसे 2026-10-17 को gemm_throughput_probe और attention_throughput_probe (B 4, H 8, T 2048) से मापा गया, commit 55fb615b पर, सिवाय H100 (251276d9) और MI300X (fc5cc954) के। कोष्ठक में दिए vendor references उसी मशीन पर मापे गए। कोई target तभी मापा हुआ गिना जाता है जब उस पर targets::families_match_the_interpreter_on_the_device pass हो जाए।

RTX 3060 पर 8192×1024 bf16 पर RMSNorm कार्ड के 360 में से 325 GB/s ले जाता है, और Nemotron-3-Diarization (bf16, चार steps) 1064 dispatches में 45.82 ms GPU time लेता है, जबकि tk3 से पहले 2292 dispatches थे।

इस रिलीज़ में नहीं

Hopper TMA और mbarrier producers (sm_90 cp.async से भरे जाने वाले wgmma चलाता है), Blackwell tcgen05, 32×32 MFMA, Apple kernels, fp8/int8, attention backward, और convolution का image-staged रूप। देखें पोर्टेबिलिटी।

पढ़ने का क्रम​

  1. आपका पहला कर्नेल: builder, GEMM के सहारे।
  2. Layouts और Lowering: program और device के बीच क्या होता है।
  3. कर्नेल लाइब्रेरी: kernels और उनके configs।
  4. Op Layer: वह API जिसे मॉडल बुलाते हैं।
  5. Tuning, टेस्टिंग और डिबगिंग, पोर्टेबिलिटी।
