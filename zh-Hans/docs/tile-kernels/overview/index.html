Tile 内核 (tk)

Svod 的优化器通过搜索循环变换，为模型的大部分计算找到快速的调度。但有些内核无法用这种方式找到。Flash attention 是一个递推：每个键块都要更新运行中的最大值与和，并重新缩放累加器，因此不存在一个可以直接分块的归约。张量核心 GPU 上的快速 GEMM 依赖多级 cp.async 环形缓冲、ldmatrix 片段加载以及带 swizzle 的共享内存布局，这些都不是循环搜索中的步骤。这类内核需要手写，而 svod-tk（“tk”）就是编写它们的 crate。

svod-tk 实现了 tile 语言的第三版（“tk3”），是唯一的 tile 内核 crate。它取代了同名的旧 crate tk1，tk1 已连同其 k-means、kNN 和 Apple 内核一起移除，这些内核均未移植。有八个模型运行在算子层上：Nemotron-3-Diarization、Whisper（编码器，以及缓存模式下解码器步骤中的注意力）、ModernBERT、BGE-M3/XLM-RoBERTa、Qwen3-Embedding、GigaAM、WavLM 和 YOLO26（通道在后布局，其 3×3 卷积使用 ops::conv2d）。

tk 是什么​

组成部分模块作用
Tile 程序ir, build基于 tile 值的结构化语句树（Let、Copy、Loop、Pipeline、If、Warps），由 Kernel 构建器按程序顺序记录。它不是 DAG。
布局layout, layouts用 F2 线性布局（比特矩阵）表示每种片段和 swizzle，由推断分配。内核代码从不指名某个 lane。
原子atoms各目标的矩阵核心指令及其操作数布局：mma.sync（CUDA）、wgmma（sm_90）、WMMA（RDNA3/3.5/4）、MFMA 16×16×16（CDNA）。
调度模板schedule把 Pipeline 展开为 cp.async 组、一或两个槽位的寄存器暂存环形缓冲，或以乒乓方式交替的两个工作组（CDNA GEMM）。作者只需编写生产与消费两部分的主体。
降级lower根据效果插入屏障、展开调度、推断布局，并输出预线性化的指令列表（Op::Linear），因此顺序不由任何拓扑排序决定。
内核kernels带尾处理（epilogue）的 GEMM、带 split-K 的隐式 GEMM 3×3 卷积、flash attention、注意力前处理（prologue）、LayerNorm/RMSNorm。每个内核输入一个 spec 结构体，输出一个 Program。
启动launch把程序作为惰性图中的自定义内核运行，降级后的主体会被记忆化缓存。
算子层opslinear、conv2d、attention、heads、layer_norm、rms_norm……它们总是返回 Tensor：有合适的内核时使用内核，否则使用计算图。
规划器ops::config依据设备测得的代价，为每种形状的配置排序。
解释器interp在主机上运行任意 tile 程序，无需 GPU 即可给出参考数值。
调优存储tune对每种形状和设备，把每个算子的候选测量一次，并把胜者保存在磁盘上。
model code ──► svod_tk::ops          always a Tensor; picks a kernel and config or builds the graph op
                   │
                   ▼
              kernels::*               spec ─► tile Program (builder, program order)
                   │
                   ▼
              lower::lower             operand loads ─► barriers ─► schedule template
                   │                   ─► layout inference ─► emission
                   ▼
              Op::Linear program  ──►  custom kernel in the lazy graph ─► LLVM ─► device

每个数字都是调优器在该卡上的选择，于 2026-10-17 用 gemm_throughput_probe 和 attention_throughput_probe（B 4、H 8、T 2048）测得，提交为 55fb615b，H100（251276d9）和 MI300X（fc5cc954）除外。括号中的厂商参考值在同一台机器上计时。只有当 targets::families_match_the_interpreter_on_the_device 在某个目标上通过后，该目标才算已测量。

在 RTX 3060 上，对 8192×1024 bf16 做 RMSNorm 的带宽为 325 GB/s（该卡上限为 360）；Nemotron-3-Diarization（bf16，四步）用 1064 次调度耗费 45.82 ms GPU 时间，而在 tk3 之前需要 2292 次调度。

本版本未包含

Hopper TMA 与 mbarrier 生产者（sm_90 运行由 cp.async 供数的 wgmma）、Blackwell tcgen05、32×32 MFMA、Apple 内核、fp8、最近邻搜索之外的 int8、注意力反向传播，以及卷积的图像暂存形式。参见可移植性。
