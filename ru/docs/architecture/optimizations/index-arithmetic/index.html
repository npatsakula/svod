Индексная арифметика

Доступ tensor[i, j] к форме [H, W] — это i * W + j. После разбиения, слияния и развёртывания диапазонов и восстановления измерений GPU индексные выражения накапливают цепочки FloorDiv/FloorMod; деление, дожившее до бэкенда, стоит десятки тактов там, где остальная часть адреса стоит один. Эта страница — целочисленная алгебра, которая их устраняет. Исходники: range_based_mod_div_patterns, advanced_division_dsl_patterns и div_mod_recombine_dsl_patterns в schedule/src/symbolic/patterns.rs, fold_divmod_general в schedule/src/symbolic/divmod.rs, понижение в schedule/src/symbolic/index_lowering.rs. Tinygrad: uop/divandmod.py, uop/symbolic.py, uop/weak.py.

В основе каждого правила лежат два факта:

  • Индексная арифметика имеет тип WeakInt, пока стадия 17 не зафиксирует её (UOp::index_const строит WeakInt); ScalarDType::Index — устаревшее имя, отсутствие которого после понижения проверяет spec.
  • Каждая перезапись проходит через exact_integer_rewrite: кандидат принимается, только если ни исходное выражение, ни замена не могут переполниться в своём конкретном dtype. Вспомогательные функции строят кандидатов в алгебре неограниченных целых; доказательство проводится в месте вызова.

Правила на основе диапазонов (range_based_mod_div_patterns)​

SoundVminVmaxProperty даёт [vmin, vmax] каждого узла (RANGE(end) — это [0, end-1]):

ПаттернРезультатGuard
RANGE(end) % end, RANGE(end) // endсам диапазон, 0тот же узел end
x % nx0 <= vmin(x) и vmax(x) < n
(a*n + b) % nb % nvmin(b) >= 0; n сравнивается по значению
(a*n + b + c) % n(b + c) % nvmin(b + c) >= 0
(a*n + b) // na, когда 0 <= b < n, иначе a + b // nn > 0, vmin(b) >= 0
x // nkvmin(x) // n == vmax(x) // n (одна корзина)
(a + (x//n)*n) // nx // n0 <= a < n
(x + c) // dx // dc > 0, d > 0, vmin(x) >= 0, и наибольший остаток, который может принять x % d, плюс c всё ещё меньше d
(x + c) // d(x + c%d) // d + c//dc % d != c, любое d != 0
(x + c) // d, x <= 0 <= x + c-(-(c%d + x - (d-1)) // d) + c//dd > 0

Первые две строки — рабочие лошадки: после разбиения RANGE(n) % n и (outer*4 + inner) // 4 — это вся история. Граница остатка в правиле (x + c) // d вычисляется по диапазону [vmin, vmax] значения x, а не по его шагу, поэтому (R*4 + 1) // 8 сворачивается, только пока R*4 принимает меньше 8 значений.

Продвинутое деление (advanced_division_dsl_patterns)​

ПаттернРезультатGuard
(a // b) // ca // (b*c)b != 0, c > 0, b*c не переполняется
expr // dexpr.divides(d)каждое слагаемое expr делится нацело (UOp::divides рекурсивно проходит через Add, так что (a + b) // c с обоими делящимися слагаемыми тоже покрыт)

Общей дистрибуции c * (a + b) для целых нет: есть только формы для WeakInt и -1 в объединении слагаемых и sym_phase3_patterns.

fold_divmod_general​

Порт fold_divmod_general из Tinygrad, вызываемый для любого скалярного целочисленного FloorDiv/FloorMod со знаменателем, чей диапазон не равен в точности {0}. Правила по порядку; побеждает первое, давшее кандидата:

  1. cancel — если у частного x // y диапазон из одного значения, вернуть его (для %: x - q*y).
  2. multiple-of guard — PARAM, объявленный multiple_of делителем, который его делит: % → 0, // не трогается.
  3. nested_div (только //) — (a % (k*c)) // c → (a // c) % k, k.vmin > 0.
  4. remove_nested_mod (только %) — (a % (k*c) + b) % c → (a + b) % c.
  5. congruence (fold_divmod_congruence) — записать x = Σ f_i t_i + k; для каждого коэффициента выбрать вычет r_i ≡ f_i (mod c) (меньший по модулю из двух знаков; для одиночного слагаемого или точной ничьей пробуются оба, в порядке itertools.product); если rem = Σ r_i t_i + k%c остаётся в одной корзине частного, то x % c = rem - bucket*c и x // c = Σ (f_i - r_i)/c · t_i + (k - k%c + bucket*c)/c. Не зависит от знака.
  6. gcd_with_remainder — при g = gcd(c, all f_i) > 1 и неотрицательном x/g: ((x/g + shift) // (c/g)) или ((x/g + shift) % (c/g)) * g + k%g.
  7. nest_by_factor — для каждого коэффициента f, который является собственным делителем c (2 <= f < c), переписать x // c как (x // f) // (c/f) (рекурсивно сворачивая внутреннее деление), а % — как ((x // f) % (c/f)) * f + x % f; побеждает кандидат с наименьшим node_count(). Ветви % нужны x >= 0 и младшая цифра, доказуемо лежащая в [0, f).
  8. divide_by_gcd (любой знаменатель) — x op y → (x/g) op (y/g) (умноженное на g для %), когда symbolic_gcd(terms, y) не равен 1. Именно это сворачивает (N*i + j) // N для символьного N.
  9. factor_remainder (любой знаменатель) — разделить слагаемые на делящиеся на y нацело и остальные; // → quotient + rest // y, % → rest % y; константный делитель также сводит коэффициент к его вычету ((r*8 + v) % 7 → (r + v) % 7). Требует x >= 0, y >= 0 и неотрицательного остатка.

Пример: (R*8 + v) // 8 с R: [0, 16), v: [0, 8) — правило 1 не срабатывает (16 корзин), правило 5 даёт вычеты 0 для коэффициента 8 и 1 для v, rem = v ∈ [0, 7] — одна корзина, так что частное — R, а остаток — v.

Рекомбинация​

fold_add_divmod_recombine на каждом Add (уровень 1): находит масштабированный остаток (base % div) * mul и партнёра q * (div*mul), где q — частное от чего-то, сравнимого с base по модулю div, и возвращает b * mul плюс остальные слагаемые — или (b % (div*d)) * mul, когда q сам является (b // div) % d. Варианты x%n + (x//n)*n → x, (x//a)%c + (x//(a*c))*c → x//a, (x%c1)*c2 + (x//c1)*(c1*c2) → x*c2 и формы со смещением — все получаются из этого одного поиска.

Понижение dtype индексов​

pm_lower_index_dtype (стадия 17-pm_lower_index_dtype, страница девекторизатора) фиксирует WeakInt в Int32 или Int64:

  • select_dtype(u): WeakFloat → float по умолчанию; целочисленные границы внутри [i32::MIN, i32::MAX] → int по умолчанию, иначе Int64.
  • Листья (CONST, VCONST, скалярные переменные PARAM) становятся concrete.cast(WeakInt); Unary, Binary, WHERE, RANGE, STACK, SPECIAL снимают приведения со своих источников и пересобираются в конкретном dtype (least_upper_dtype от select_dtype(u) и источников для бинарной операции); слабый INDEX приводит свой буфер и фиксирует свои индексы; неслабый потребитель поглощает замыкающее приведение на собственном ребре (lower_weak_srcs, с мемоизацией на ядро).
  • WHERE(valid, idx, Invalid) сохраняет свою форму; Invalid никогда не приводится. Индекс с гейтом, получившийся Int64, сужается обратно до Int32, если число элементов буфера укладывается в i32.

WHERE валидности становится gate у LOAD/STORE двумя стадиями позже, в pm_move_gates_from_index (late/gater.rs); у самого INDEX поля гейта нет.

Разобранный пример​

tensor[i, j] формы [4, 8], обходимый плоско по 32 элементам через R0 ∈ [0, 32):

row = R0 // 8, col = R0 % 8
addr = row * 8 + col = (R0 // 8) * 8 + (R0 % 8)

Рекомбинация сразу даёт addr = R0. Теперь развернём на 4: pm_split_ranges подставляет R0 = R1 * 4 + R2 с R1 ∈ [0, 8), R2 ∈ [0, 4):

row = (R1*4 + R2) // 8
col = (R1*4 + R2) % 8

Запуск graph_rewrite(symbolic(), ..) на этих выражениях (деревья ниже — его вывод):

row = (R1*4 + R2)//8
[31] FloorDiv : Scalar(WeakInt) shape=[]
├── [13] RANGE(R1, Weak) : Scalar(WeakInt) shape=[]
│   └── [2] CONST(Int(8)) : Scalar(WeakInt) shape=[]
└── [29] CONST(Int(2)) : Scalar(WeakInt) shape=[]

col = (R1*4 + R2)%8
[55] Add : Scalar(WeakInt) shape=[]
├── [54] Mul : Scalar(WeakInt) shape=[]
│   ├── [50] FloorMod : Scalar(WeakInt) shape=[]
│   │   ├── [13] RANGE(R1, Weak) : Scalar(WeakInt) shape=[]
│   │   │   └── [2] CONST(Int(8)) : Scalar(WeakInt) shape=[]
│   │   └── [46] CONST(Int(2)) : Scalar(WeakInt) shape=[]
│   └── [14] CONST(Int(4)) : Scalar(WeakInt) shape=[]
└── [15] RANGE(R2, Weak) : Scalar(WeakInt) shape=[]
    └── [14] → (see above)

row: правило 1 не срабатывает (четыре корзины), congruence не срабатывает (rem = R1*4 + R2 ∈ [0, 31] охватывает четыре корзины), gcd(8, 4, 1) = 1, а nest_by_factor с f = 4 сворачивает (R1*4 + R2) // 4 в R1 по congruence (rem = R2 ∈ [0, 3]) и оставляет R1 // 2. col: тот же множитель даёт (R1 % 2) * 4 + R2. Если собрать обратно, row*8 + col рекомбинируется в R1*4 + R2 — адрес снова линейный, хотя row и col по отдельности всё ещё несут деление и остаток. Разобьём ещё раз, R1 = R3 * 2 + R4 (R3 ∈ [0, 4), R4 ∈ [0, 2)), и правила на основе диапазонов доводят дело до конца:

row = (R3*8 + R4*4 + R2) // 8   → R3                (a*n + b)//n with b = R4*4 + R2 ∈ [0, 7]
col = (R3*8 + R4*4 + R2) % 8    → R4*4 + R2         (a*n + b + c)%n, then x % n → x
addr = row*8 + col              → (R4*4 + R2) + R3*8

Ноль делений, ноль остатков: адрес с тайлингом совпадает с плоским адресом, что доказано перезаписью. Ещё два результата того же запуска: (R*8 + v) // 8 с R: [0, 16), v: [0, 8) → R (правило 5) и (R*8 + v) % 7 → (R + v) % 7 (сведение коэффициента в правиле 9).
