Оптимизация диапазонов и редукций

Правила, которые решают, какие циклы существуют: разбиение, слияние и сужение диапазонов, сведение редукций к замкнутым формам, встраивание или материализация промежуточных значений. Они находятся в schedule/src/rangeify/{patterns,transforms,kernel}.rs и выполняются в мега-проходе rangeify, при разрезе на ядра и в apply_pre_optimization (порядок — на странице Rangeify). Tinygrad: schedule/rangeify.py, codegen/simplify.py.

Разбиение диапазонов (pm_split_ranges)​

RANGE % c с end % c == 0 помечает диапазон; на SINK каждый помеченный диапазон заменяется на outer * c + inner с outer = RANGE(end / c) и inner = RANGE(c); оба сохраняют тип оси и получают идентификаторы осей axis.child(0) / axis.child(1) (без глобального выделения id). Диапазоны Warp и Device никогда не разбиваются; каждый диапазон, которым индексируется STORE изображения, закреплён, потому что адрес изображения — пара координат, а не плоское смещение. Граф после подстановки упрощается через symbolic + pm_fold_cast_const, так что inner % c → inner и (outer*c + inner) // c → outer срабатывают сразу.

Слияние и сужение диапазонов (pm_simplify_ranges)​

simplify_merge_adjacent выполняется на каждом END и REDUCE хотя бы с двумя диапазонами. Для END он пробует соседние пары; для REDUCE — каждую упорядоченную пару. Пара (r0, r1) сливается, когда у обоих одинаковый тип оси, константные концы и они встречаются в одних и тех же REDUCE (согласованная область видимости): слитый диапазон R(s0*s1) заменяет r0 на R // s1, а r1 — на R % s1, граф упрощается через symbolic + pm_fold_cast_const + pm_flatten_range, и слияние сохраняется, только если число FloorDiv/FloorMod не выросло (count_divmod, с мемоизацией на узел). Символьный конец никогда не сливается: число divmod не изменилось бы, а символьное произведение скрыло бы константную ось от всех последующих оптимизаций, работающих только с константами (upcast, unroll, locals, тензорные ядра).

mark_gated собирает из каждого INDEX границу, которую каждая клауза валидности range < c доказывает для диапазона; диапазон, где-либо использованный без защиты, закрепляется на собственном конце, а диапазоны REDUCE защищены. На SINK каждый ограниченный диапазон пересобирается с наибольшей доказанной границей, и результат упрощается. Вместе с pm_flatten_range (списки диапазонов заново выводятся из RANGE, достижимых через источники, обратные рёбра Bool/Void сохраняются) это и есть вся стадия «упрощение диапазонов».

Схлопывание загрузок (pm_load_collapse)​

reduce_load_collapse(src, ranges), для каждого диапазона: взять узлы в области видимости диапазона (выйти при вложенном REDUCE или STORE), заменить каждый внешний вход, не являющийся константой или PARAM, скалярной переменной PARAM in{n}, несущей его vmin/vmax (UOp::variable), обернуть тело в синтетический REDUCE(Add) по этому диапазону и запустить build_reduce_load_collapse_matcher. Если ни один RANGE не выжил, подставить переменные обратно. Матчер — это pm_reduce_collapse плюс формы .or_casted() и подъём NE.

Правила границ (reduce_collapse_inner_patterns, simplify.py в Tinygrad):

Тело редукции (по r ∈ [0, N))Замкнутая форма
WHERE(r < cut, 0, v)clamp(N - cut, 0, N) * v
WHERE(r < cut, v, 0)clamp(cut, 0, N) * v
WHERE(r >= lo & r < hi, v, 0)двусторонний clamp, умноженный на v
WHERE(idx != r, 0, e), WHERE(idx == r, e, 0) (gather)WHERE(0 <= idx < N, e[r := idx], 0)

(min внутри clamp записывается как -max(-a, -b), чтобы правило границ Max могло закрыть граничные случаи.) Вокруг них: pm_reduce_unparented; подъёмные преобразования, открывающие границы, — (x + y) < c → x < c - y и (x*y) < c → x < ceil(c/y), также сквозь CAST, аналогично для >= и ==, != в варианте схлопывания загрузок; дистрибутивное sum(x + y) → sum(x) + sum(y); x * bool.cast() → WHERE(bool, x, 0); try_param_factor для условия, которое является клаузой PARAM без диапазона, объединённой через AND с клаузой диапазона. Внешний pm_load_collapse также отменяет поднятое (x + y) < c, когда x содержит загрузку, так что загруженные индексы никогда не переполняются. Тот же движок с более узким матчером (без подъёма !=) — это reduce_collapse, используемый pm_reduce_simplify в мега-проходе для REDUCE(Add) с num_axes == 0.

sum(1 for k in 0..64 if k >= length)   →   max(0, 64 - length)

Неиспользуемые диапазоны редукции и вынос множителей (pm_reduce_simplify)​

pm_reduce_unparented: диапазон редукции, на который тело не ссылается, удаляется — Add умножает результат на протяжённость, Mul возводит его в степень протяжённости, Max отбрасывает диапазон; Min не сопоставляется. reduce_mul_chain: в REDUCE(a * b * .., Add | Max) множители, не зависящие ни от одного диапазона редукции, выносятся наружу (для Max — только доказуемо неотрицательные), только для целых. Оба также выполняются в POST_OPT_SYM (стадия 08) и на уровне sym.

Удаление буферов (pm_remove_bufferize)​

INDEX(STAGE(src, ranges, opts), indices) встраивается подстановкой индексов потребителя вместо диапазонов стадии (substitute_gated; диапазоны CONST и индексы Invalid пропускаются), если только:

  1. src не является всегда исполняемой операцией (CONTIGUOUS, COPY, NOOP) и стадия не является неудаляемой (потребитель COPY, всегда непрерывный источник, граница материализации с несколькими потребителями, вход пользовательского ядра);
  2. вычисление не читает больше трёх различных буферов (буферы AFTER, глобальные STAGE, MSTACK, PARAM/BUFFER), что раздуло бы список аргументов ядра;
  3. REDUCE внутри вычисления не читает буфер (PARAM, BUFFER или STAGE) — встраивание повторяло бы чтение на каждой итерации (argmax(-x) загружал бы x N раз вместо одного). Редукция по значениям, не касающимся буферов, по-прежнему встраиваема.

За подстановкой следуют два правила очистки: STORE(x, x) → NOOP, END(NOOP) → NOOP.

buffer_folding: STAGE(CONST), INDEX(CONST), COPY(CONST) и INDEX(MSTACK(CONST, ..)) сворачиваются в константу; INDEX(STAGE(compute, ranges), ranges) с теми же диапазонами — это compute, суженный до формы стадии, с объединением тегов.

dead_axis_removal: удаляемый STAGE (не над AFTER или всегда исполняемой операцией, без символьного конца) отбрасывает диапазоны, которые являются CONST или не используются вычислением, затем через RESHAPE возвращает измерения размера 1 и через EXPAND восстанавливает исходную форму. Стадия может остаться без диапазонов; она всё равно должна существовать, иначе при разрезе не будет создан STORE.

Двухстадийные редукции (split_reduceop)​

В самой ранней перезаписи REDUCE в тензорной форме, у которого отношение входа к выходу достигает SplitReduceOpConfig::split_threshold (32768), разбивается: редуцируемое измерение, которое не является broadcast (detect_expanded_dimensions) и делится на делитель из [8, 256] (начиная с наибольшего) так, что промежуточный выход остаётся меньше 2^22 элементов, переформируется в [.., divisor, rest, ..], редуцируется по исходным осям, материализуется через CONTIGUOUS и редуцируется снова по оси делителя. У первой стадии тогда divisor выходов для распараллеливания; вторая мала.

Групповые редукции​

Это не правило rangeify, но из того же семейства: опции GROUP/GROUPTOP превращают часть оси Reduce в GroupReduce, а pm_group_for_reduce (стадия 10) понижает её до частичного REDUCE, размещённого в локальной памяти, считываемого обратно свежими циклами Reduce (axis_id.group_reduce_loop()) и редуцируемого снова. См. страницу expander.
