Измерения GPU, девекторизация и понижение индексов (стадии 12–18)

После понижения редукций ядро всё ещё оперирует значениями с формой и индексами WeakInt. Эти стадии отображают диапазоны на аппаратные индексы, делают каждый доступ к памяти явным скалярным LOAD/STORE, снова расширяют непрерывные доступы и фиксируют dtype индексов. Исходники: gpudims.rs, devectorize.rs, late/coalesce.rs, symbolic/index_lowering.rs.

12 — измерения GPU​

Два матчера. pm_lower_device_ranges запускается для любого рендерера: диапазон Device становится скалярной переменной PARAM _device_num с границами диапазона, а END, который его закрывал, теряет эту запись. pm_add_gpudims запускается, только если renderer.has_local || renderer.has_threads; он сопоставляет SINK один раз (GpuDimsContext запоминает id пониженного sink, так что повторный визит движка ничего не делает).

add_gpudims:

  1. Собирает все RANGE с ключом (axis_id, axis_type); выходит, если SPECIAL уже существует.
  2. Глобальные измерения — оси Global и Thread; локальные — Local, Warp, GroupReduce. Обе группы сортируются по id оси; ось Warp переносится в начало локальных, чтобы ей принадлежали младшие биты линейного индекса потока (mma.sync адресует фрагменты по аппаратной линии).
  3. Строит индексные выражения:
    • has_threads (CPU): ровно одна глобальная ось и ни одной локальной, иначе проход отказывается с предупреждением. Ось становится PARAM("core_id", 0..N-1).
    • KernelInfo.dont_use_locals: только глобальные, get_grouped_dims("idx", ..).
    • иначе lidx* из локальной формы под local_max_axes() (или local_max на ось; ведущее ограничение закреплено на протяжённости warp, чтобы ничто другое не сворачивалось в lidx0), затем gidx* из глобальной формы под global_max, дополнительно ограниченные global_prod_max / hardware_local_extents, если рендерер объявляет лимит произведения work-item.
  4. get_grouped_dims взят из Tinygrad: если измерения не укладываются в ограничения на ось, group_dims сливает соседние измерения, чьё произведение укладывается; если ничего сгруппировать не удалось, split_dims раскладывает слишком большое измерение по его наименьшему делителю в следующий слот. Любая неудача вызывает панику на этапе планирования, а не кодогенерации ("cannot limit dims to N axes"). Результат — один SPECIAL(end, "gidxN") на ограниченное измерение; если происходило группирование или разбиение, каждое исходное измерение восстанавливается из плоского индекса через FloorDiv/FloorMod и упрощается symbolic. Глобальные индексы строятся с reverse = true (рекурсия разворачивает и вход, и выход, поэтому имена остаются в порядке итерации).
  5. Маскирование записей (compute_store_masks): STORE в глобальную память, индекс которого не находится в области видимости каждого локального диапазона, получает на индексе WHERE((l1 == 0) & (l2 == 0) & .., idx, Invalid), так что пишет только один work-item на каждую неиспользуемую локальную ось. Маска остаётся внутри индексного выражения, поэтому подстановка RANGE → SPECIAL доносит её до аппаратного индекса.
  6. Подставляет вместо каждого GPU-диапазона его индекс; диапазоны Reduce остаются циклами.

На CPU-примере со страницы разобранного примера ничего не происходит: ось строк — Weak (ось Thread не создавалась), а у рендерера нет локальных измерений.

13 — загрузки​

PM_ADD_LOADS = symbolic_simple() + pm_expand_broadcast() + pm_add_loads().

  • pm_expand_broadcast снова начинается с pm_wmma_add, затем делает broadcast явным: у Binary/Ternary/STORE с источниками разной формы каждый источник получает RESHAPE (ведущие единицы) и EXPAND до формы broadcast; WMMA, у которого префиксы операндов различаются, разворачивается по каждой выходной координате (broadcast_and_devec_wmma).
  • pm_add_loads оборачивает в LOAD каждый операнд, потребляемый как значение: источники ALU-операций, приведений типа, REDUCE, WMMA и STACK, у которых есть адресное пространство (maybe_load), а также значение STORE, которое само является адресом. INDEX, используемый как адрес, — цель STORE, указатель на фрагмент WMMA — остаётся без обёртки. Чтения аккумулятора, созданные на стадии 10 (AFTER(acc, ..)), здесь становятся LOAD(AFTER(acc, ..)).

14 — девекторизация​

devectorize() — один graph_rewrite поверх symbolic_simple + devectorize_patterns + bool_storage_patterns + indexing_simplify (контекст Renderer, правилами не используется). Внешнего цикла нет: движок заново сопоставляет каждую замену.

devectorize_patterns (devectorizer2 в Tinygrad) в порядке исходника:

ГруппаПравила

devectorize_alu — это do_devectorize из Tinygrad: он требует, чтобы каждый источник имел форму результата (или был базой Invalid, чей скаляр полиморфен), перечисляет координаты статической формы, строит по одной скалярной операции на координату с операндами INDEX(source, c0, c1, ..) и собирает результат через stack_with_shape (вложенные STACK, повторяющие форму) — или GROUP для STORE. Число линий — полное произведение формы; ширины свёртки, зависящей от устройства, нет. Обратная векторизация — задача бэкенда (SLP-векторизатор LLVM или, для памяти, memory_coalescing двумя стадиями позже).

bool_storage_patterns: bool STORE приводится к uint8, bool LOAD загружает uint8 и приводит обратно, BITCAST, затрагивающий bool, становится CAST. В i1 у LLVM старшие биты могут содержать мусор.

indexing_simplify (late/coalesce.rs): для INDEX(buf, WHERE(valid, idx, Invalid)) функция uop_given_valid переписывает idx в предположении, что valid истинно (symbolic/valid_simplification.rs); двухкоординатная форма изображения дополнительно отбрасывает клаузы валидности, которые уже следуют из границ изображения (drop_valid_stmts).

После этой стадии каждая ALU-операция скалярна. В разобранном примере четыре линии индексного выражения становятся четырьмя LOAD(INDEX(PARAM, R0*4 + R1*64 + k)), а горизонтальная цепочка Add становится явной.

15 — раннее символьное упрощение​

Ещё раз sym(), теперь на скалярном коде. Причина его существования — следующая стадия: индексные выражения должны быть в канонической форме base + const, прежде чем слияние доступов сможет их сгруппировать.

16 — слияние доступов к памяти​

memory_coalescing (late/coalesce.rs) — обход графа, а не матчер. Он группирует LOAD и STORE без гейтов по (op, buffer, index base, validity), где индекс разбит на base + integer_offset (индекс Invalid или константа — сам себе база). Внутри группы последовательные смещения образуют серии; каждая серия режется на самую широкую длину свёртки, которая делит базовое смещение:

  • буферы изображений: 4;
  • рендереры с supports_float4: степени двойки начиная с 16 / sizeof(dtype) при access_bytes() >= 16 (восемь 16-битных линий, четыре f32), иначе начиная с 4;
  • иначе только скаляр. Буферы Reg и несворачиваемые dtype (всё, кроме f32/f16/bf16/i32/u32/fp8) остаются скалярными.

Свёртка ширины n > 1 становится LOAD(SHRINK(buf, offset, n)), а старые загрузки заменяются на INDEX(load, lane), либо STORE(SHRINK(..), STACK(values)). SHRINK несёт форму группы; dtype памяти остаётся скалярным. DMC=1 отключает проход. В разобранном примере четыре развёрнутые загрузки становятся одной LOAD(SHRINK(PARAM(1), R0*4 + R1*64, 4)), которую бэкенд LLVM рендерит как load <4 x float>.

17 — поэлементный проход / проход изображений снизу вверх​

symbolic_simple + no_vectorized_alu + pm_simplify_add_image, применяется через graph_rewrite_bottom_up с AddImageContext. Правила для изображений канонизируют доступы f16 к буферам изображений f32 (LOAD → LOAD.cast(f16), STORE(value.cast(f32)), отбрасывание кругового CAST(CAST(x, f16), f32)). Создание буферов изображений в Svod не поддерживается ни одной целью; правила лишь обслуживают существующие доступы к изображениям. no_vectorized_alu запускается снова, потому что перезапись изображения может вернуть операцию с формой.

16 — дополнительное символьное упрощение​

extra_symbolic_patterns = sym() + indexing_simplify(). Индексы здесь намеренно всё ещё WeakInt: дистрибутивным правилам и правилам валидности индексов из sym и indexing_simplify нужен слабый dtype, так что это их последний шанс. (Метка совпадает с меткой слияния доступов; обе печатаются при SVOD_DUMP_STAGE=16.)

17 — понижение dtype индексов​

lower_index_patterns = symbolic_simple + pm_fold_cast_const + pm_lower_index_dtype + indexing_simplify, с одним WeakMemo на ядро (единственный ctx={} в Tinygrad). Порт tinygrad/uop/weak.py.

select_dtype(u): WeakFloat → float по умолчанию; целое, чьи vmin/vmax укладываются в i32 → int по умолчанию, иначе Int64; число векторных элементов сохраняется.

pm_lower_index_dtype компонует:

  1. pm_commit_weak — Binary/Ternary со слабым источником и неслабым least_upper_dtype фиксирует слабые источники в нём (commit_weak: у CONST меняется тип, всё остальное приводится); STORE, чьё значение слабое, фиксирует его в dtype индекса.
  2. pm_cast_weak — CAST(weak_alu, concrete) проталкивает конкретный dtype в источники ALU.
  3. Смещения/размеры SHRINK фиксируются через select_dtype.
  4. Любой неслабый узел со слабыми источниками → lower_weak_srcs: каждый слабый источник переписывается через pm_lower_weak (с мемоизацией по id источника), а замыкающий слабый CAST поглощается собственным ребром потребителя. pm_lower_weak — трёхфазный каскад:
    • листья: CONST/VCONST/скалярный PARAM становятся concrete.cast(weak);
    • Unary, Binary, WHERE (условие пропускается), RANGE, STACK, SPECIAL (lower_weak_node): снять слабые приведения с источников, вычислить конкретный dtype (least_upper_dtype от select_dtype(u) и источников для бинарных операций; иначе dtype_from_op), привести к нему каждый источник, оставить слабый CAST на результате, если это не STACK;
    • INDEX со слабым dtype: буфер приводится к выбранному dtype, и каждый слабый индекс фиксируется;
    • CAST(weak, CAST(weak, x)): внутреннее приведение фиксируется, внешнее сохраняется.
  5. INDEX (или SHRINK), чей индекс с гейтом уже получился Int64, сужается обратно до Int32, если число элементов буфера укладывается в i32.

Это стадия, на которой WHERE(valid, idx, Invalid) сохраняет свою форму: lower_weak_node не трогает источники Invalid. В разобранном примере каждый WeakInt становится Int32 (RANGE(R0, Reduce) : Scalar(Int32)), а размеры PARAM становятся константами Int32.

18 — финальное символьное упрощение​

symbolic() (уровень 2, без pm_simplify_valid/свёрток линий) на графе с конкретными типами. При включённом SVOD_SPEC функция verify_no_legacy_index_dtype проверяет, что ни один WeakInt не выжил.
