Tile-ядра (tk)

Оптимизатор Svod находит быстрые расписания для большей части модели перебором преобразований циклов. Но некоторые ядра так не найти. Flash attention — это рекуррентность: каждый блок ключей обновляет текущие максимум и сумму и перемасштабирует аккумулятор, так что единой редукции, которую можно разбить на тайлы, нет. Быстрый GEMM на GPU с тензорными ядрами держится на многоступенчатом кольце cp.async, загрузках фрагментов через ldmatrix и swizzled-раскладке разделяемой памяти — всё это не шаги перебора циклов. Такие ядра пишутся вручную, и svod-tk («tk») — крейт для их написания.

svod-tk реализует третью версию тайлового языка («tk3») и остаётся единственным крейтом tile-ядер. Он заменил tk1, прежний крейт с тем же именем, который удалён вместе со своими ядрами k-means, kNN и ядрами для Apple; ни одно из них не перенесено. На слое операций работают восемь моделей: Nemotron-3-Diarization, Whisper (энкодер и внимание шага декодера в режиме кэша), ModernBERT, BGE-M3/XLM-RoBERTa, Qwen3-Embedding, GigaAM, WavLM и YOLO26 (channels-last, свёртки 3×3 на ops::conv2d).

Что такое tk​

ЧастьМодульЧто делает
Тайловая программаir, buildСтруктурированное дерево инструкций (Let, Copy, Loop, Pipeline, If, Warps) над тайловыми значениями, которое билдер Kernel записывает в порядке программы. Это не DAG.
Раскладкиlayout, layoutsЛинейные раскладки над F2 (битовые матрицы) для каждого фрагмента и swizzle, назначаемые выводом. Код ядра никогда не называет лейн.
АтомыatomsИнструкции матричных ядер каждой цели вместе с раскладками операндов: mma.sync (CUDA), wgmma (sm_90), WMMA (RDNA3/3.5/4), MFMA 16×16×16 (CDNA).
Шаблоны расписанияscheduleРазворачивают Pipeline в группы cp.async, регистровое кольцо из одного или двух слотов или две бригады в режиме ping-pong (GEMM на CDNA). Автор пишет только тела produce и consume.
ПонижениеlowerВставляет барьеры по эффектам, разворачивает расписание, выводит раскладки и выпускает заранее линеаризованный список инструкций (Op::Linear), так что порядок не решает никакая топологическая сортировка.
ЯдраkernelsGEMM с эпилогами, неявная GEMM-свёртка 3×3 со split-K, flash attention, пролог внимания, LayerNorm/RMSNorm. На входе каждого — структура-спецификация, на выходе — Program.
ЗапускlaunchЗапускает программу как пользовательское ядро в ленивом графе, мемоизируя пониженные тела.
Слой операцийopslinear, conv2d, attention, heads, layer_norm, rms_norm, … Всегда возвращают Tensor: используют ядро, когда оно подходит, и граф в остальных случаях.
Планировщикops::configРанжирует конфигурации для каждой формы по измеренным стоимостям устройства.
ИнтерпретаторinterpИсполняет любую тайловую программу на хосте и даёт эталонные числа без GPU.
Хранилище тюнингаtuneЗамеряет кандидатов каждой операции один раз на форму и устройство и сохраняет победителя на диске.
model code ──► svod_tk::ops          always a Tensor; picks a kernel and config or builds the graph op
                   │
                   ▼
              kernels::*               spec ─► tile Program (builder, program order)
                   │
                   ▼
              lower::lower             operand loads ─► barriers ─► schedule template
                   │                   ─► layout inference ─► emission
                   ▼
              Op::Linear program  ──►  custom kernel in the lazy graph ─► LLVM ─► device

Каждое число — выбор тюнера на этой карте, замеренный 2026-10-17 с помощью gemm_throughput_probe и attention_throughput_probe (B 4, H 8, T 2048) на коммите 55fb615b, кроме H100 (251276d9) и MI300X (fc5cc954). Эталоны вендоров в скобках замерены на той же машине. Цель считается замеренной, только когда на ней проходит targets::families_match_the_interpreter_on_the_device.

На RTX 3060 RMSNorm над 8192×1024 bf16 прокачивает 325 GB/s из 360 доступных карте, а Nemotron-3-Diarization (bf16, четыре шага) занимает 45.82 ms времени GPU за 1064 запуска против 2292 запусков до tk3.

Не в этом релизе

Производители на Hopper TMA и mbarrier (sm_90 выполняет wgmma, питаемый через cp.async), Blackwell tcgen05, MFMA 32×32, ядра Apple, fp8/int8, обратный проход внимания и вариант свёртки с подготовкой изображения в разделяемой памяти. См. Переносимость.
