Тестирование и отладка

Каждое ядро tk проверяется на двух уровнях. На хосте его тайловая программа выполняется в интерпретаторе и сверяется с прямым эталоном, а пониженная программа рендерится и, где установлен тулчейн, компилируется для каждой цели. На GPU с ядрами tk (CUDA или AMD) пониженное ядро сверяется с интерпретатором или с графовым запасным вариантом самой операции. Тесты сравнивают значения с допусками, а не хэши IR.

Интерпретатор​

interp::run(&program, params, vars) исполняет тайловую программу на хосте. Он принимает по одному Vec<f64> на параметр и возвращает все параметры после выполнения. Каждый блок выполняет свои инструкции по порядку, а конвейер выполняется как последовательное чередование. Каждое значение округляется до своего типа элемента (interp::round_to), так что результат — то, что корректное понижение должно воспроизвести с точностью до порядка накопления. Скалярное деление округляет к нулю, как и выпущенный код. Переменные времени выполнения связываются по имени:

let out = run(&prog, vec![a.clone(), b.clone(), vec![0.0; m * n]], &[("b", 1)]).unwrap();

Он возвращает interp::Error::{UnboundVar, ParamSize, Division, OutOfBounds}: обращение за пределы ёмкости буфера — это ошибка, а не молчаливое чтение. Потоки и барьеры он не моделирует, поэтому ошибки упорядочивания проявляются только на устройстве.

Запуск набора тестов​

SVOD_DEVICE выбирает устройство. Тесты на устройстве пропускаются со строкой skipped: … только там, где запускать не на чем: SVOD_DEVICE=CPU, GPU, для которого у tk нет ядер, или нет ни SVOD_DEVICE, ни подключённого поддерживаемого GPU. Если поддерживаемый GPU подключён, а SVOD_DEVICE не задан, они падают и называют значение, которое нужно задать: набор, в котором все тесты на устройстве пропущены, проходит и ничего не доказывает.

# Host only, no GPU:
SVOD_DEVICE=CPU cargo test -p svod-tk --release --lib
# On the GPU; on a fresh tune store run the cost probes alone first, since the parallel
# suite inflates what they measure and the store keeps the first measurement:
SVOD_DEVICE=CUDA cargo test -p svod-tk --release --lib device_costs_are_physical
SVOD_DEVICE=CUDA cargo test -p svod-tk --release --lib

SVOD_DEVICE=AMD (или AMD:N, в порядке узлов KFD) выбирает GPU AMD. Цель считается замеренной, только когда на ней проходит families_match_the_interpreter_on_the_device: первый кандидат каждого семейства на устройстве против интерпретатора. register_staged_families_match_on_cuda прогоняет путь данных AMD (заполнение через регистры, без ldmatrix) на GPU CUDA.

На новом GPU​

  1. Направьте хранилище тюнинга в каталог, который нужно сохранить: SVOD_TK_TUNE_DIR=$PWD/tk_tune_$(hostname).
  2. На машине с несколькими узлами AMD проверьте, что узел, который называет SVOD_DEVICE=AMD:N, — это GPU (/sys/class/kfd/kfd/topology/nodes/*/properties, gfx_target_version).
  3. Запустите отдельно device_costs_are_physical, затем families_match_the_interpreter_on_the_device, затем весь набор. Не публикуйте числа для устройства, на котором гейт не проходит.

Проверка на уровне модели для Nemotron (настоящие веса, сгенерированные эталоны):

SVOD_DEVICE=CUDA cargo test -p svod-model --release --lib nemotron_diar::parity::half_precision -- --ignored --nocapture --test-threads=1

Запустилось ли ядро?​

Операция, ушедшая на запасной вариант, строит операции графа вместо CALL; тесты в ops.rs ищут имя ядра среди вызовов графа результата. Чтобы предсказать путь без устройства, вызовите планировщик ops::shape (см. Слой операций); на устройстве журнал планировщика говорит, почему операция ушла на граф (Тюнинг).

Планирование для другой карты​

Пример tk_dump показывает, что tk запустил бы на карте, которой на этой машине нет: ранжирование планировщика с предсказанными ns и причину, по которой не вошла каждая конфигурация решётки (plan.txt), текст LLVM выбранной конфигурации и, где установлены инструменты, её PTX, ресурсы ptxas -v и SASS (CUDA) или ассемблер AMDGCN с комментариями о ресурсах (AMD), а также гистограмму опкодов главного цикла.

cargo run -p svod-tk --release --example tk_dump -- --card h100-pcie --op gemm --shape 4096x4096x4096
cargo run -p svod-tk --release --example tk_dump -- --arch gfx942 --op attention --shape 8x16x1024x128 --causal --store DIR

--card принимает имя из atoms::CARDS (rtx3060, h100-pcie, h100-sxm, rtx5070, rtx5090, mi300x, mi355x, rx9070xt, strix-halo); --arch принимает архитектуру с --sms/--xcds или с параметрами первой карты из списка. --store — каталог хранилища тюнинга, скопированный с карты, строки проб которого задают цены ранжирования; без него это делают угаданные стоимости. --cfg N выпускает N-ю ранжированную конфигурацию, --out DIR задаёт выходной каталог (tk_dump).

--op принимает gemm (--shape MxNxK), attention (BxHxTxD), norm (RxD), conv (BxHxWxCINxCOUT) или heads (BxTxHxKVxD), каждый через собственные проверку формы и тюнинг слоя операций. --cfg tuned выпускает конфигурацию, которую тюнер выбрал на карте, читая её из копии --store и ничего в неё не записывая: сохранённая строка совпадает по операции, устройству, типу, форме и списку конфигураций, по которому её ключует слой операций, каким бы компилятором и какой бы сборкой ядер она ни была записана; дамп печатает каждый прочитанный ключ или говорит, какой строки нет. --compare FILE [--fun NAME] печатает главный цикл эталонного ядра (.cubin, объект кода AMD или текст SASS, PTX либо AMDGCN) рядом с главным циклом tk, посчитанным тем же способом.

cargo run -p svod-tk --release --example tk_dump -- --card rtx3060 --op gemm --shape 4096x4096x4096 --cfg tuned --store ~/.cache/svod/tk_tune
cargo run -p svod-tk --release --example tk_dump -- --card mi300x --op gemm --shape 4096x4096x4096 --compare hk.co --fun NAME

Переменные окружения​

ПеременнаяЭффект
SVOD_DEVICEУстройство по умолчанию: CUDA[:N], AMD[:N], CPU. Решает, применимы ли ядра и какие тесты на устройстве запускаются
SVOD_TK_TUNE=0Без замера кандидатов; работает первая чистая конфигурация (см. Тюнинг)

Профилирование модели​

Пример Nemotron один раз прогревается (заодно заполняя хранилище тюнинга), затем замеряет и профилирует второй запуск и печатает его поядерный отчёт:

cargo run -p svod-model --release --example nemotron_diarize -- audio_1.wav --dtype bf16 --profile

Ядра tk появляются под своими именами (gemm, conv, flash_attention, heads, layer_norm, …) рядом с ядрами графа и замеряются так же.

Замеряйте на тихом GPU

Любой другой процесс на GPU искажает все числа. Пробы и хранилище тюнинга сначала прогревают частоту. Запускайте пробы с --test-threads=1.
